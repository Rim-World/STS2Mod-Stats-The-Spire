## 3. 许可证验收

### LIC-01 根目录许可证包含上游署名

**为什么验**

项目代码来自上游公开源码。上游仓库没有声明许可证，因此本项目不能把上游代码当作 MIT 代码重新授权。许可证必须同时写明上游作者和授权范围。

**操作**

1. 打开项目根目录的 `LICENSE`。
2. 阅读 MIT 正文之前的 `Upstream attribution and scope` 段。
3. 核对以下内容：
   - 上游作者 `reddots1453`。
   - 上游仓库地址 `https://github.com/reddots1453/STS2mod-Stats_the_Spire`。
   - 上游仓库未声明许可证。
   - MIT 只覆盖本维护仓库新增或修改的代码。
   - MIT 不覆盖上游代码。

**通过标准**

- 以上五项都存在。
- 没有把上游代码整体声明为 MIT。
- MIT 正文仍然完整。

**失败示例**

- 只有 `Copyright (c) 2026 Rim-World`，没有上游署名。
- 写成上游代码也由本项目 MIT 授权。
- 上游仓库地址或作者写错。

**记录**

```text

备注：
```

### LIC-02 三份许可证与 README 表述一致

**为什么验**

根目录、源码目录和当前输出包各有一份 `LICENSE`。输出包会交给使用者；三份内容不一致会造成授权范围歧义。

**操作**

1. 打开以下三份文件：
   - `LICENSE`
   - `9.SRC/LICENSE`
   - `10.OUTPUT/1.9.0/LICENSE`
2. 比较开头署名段是否一致。
3. 打开根目录 `README.md` 的「来源与授权」段。
4. 打开 `9.SRC/README_ZH.md`、`9.SRC/README_EN.md` 的许可证段。
5. 打开 `10.OUTPUT/1.9.0/README_ZH.md`、`README_EN.md` 的许可证段。
6. 核对 README 是否写明「上游未声明许可证；MIT 仅覆盖本维护仓库新增与修改的代码」。

**通过标准**

- 三份 `LICENSE` 内容一致。
- README 中英文表述一致。
- README 没有暗示上游代码已获得 MIT 授权。

可选命令：

三行哈希应相同。

### AC-033-01 设置页入口与语言项

**为什么验**

1.9.0 删除了 Mod 自己的语言选项，语言改为跟随游戏。设置页是用户接触该变化的第一入口。

**操作**

1. 启动 v0.113.1。
2. 从主菜单打开 RitsuLib 的 Mod 设置入口。
3. 找到 `Stats the Spire` 设置页。
4. 确认页面没有语言下拉项。
5. 进入一局游戏，打开暂停菜单，再次进入同一设置页。
6. 确认暂停菜单入口也能打开。

**通过标准**

- 主菜单可打开设置页。
- 跑局暂停菜单可打开设置页。

- 仍有语言下拉项。
- 暂停菜单打不开设置页。
- 打开后报错或空白。

**解释**

语言项被删除是设计变更，不是功能缺失。设置页仍保留热键、意图面板缩放和功能开关。

### AC-033-07 物理 Ctrl+F8 热键

**为什么验**

默认热键已从单键 `F8` 改为 `Ctrl+F8`。当前安装中的 `Rewind` 模组仍占用 `F8`，单键 F8 可能触发其他功能。

**操作**

1. 进入一局游戏。
2. 按 `Ctrl+F8`。
3. 观察贡献面板是否显示。
4. 再按一次 `Ctrl+F8`。
5. 观察面板是否隐藏。
6. 打开开发者控制台，或进入任意可输入文本的输入框。
7. 在输入状态按 `Ctrl+F8`。
8. 观察贡献面板是否被切换。

**通过标准**

- 跑局中 `Ctrl+F8` 可正常开关贡献面板。
- 文本输入或控制台输入时，`Ctrl+F8` 不触发面板切换。
- 不需要按单键 `F8`。
- 没有报错或按键冲突提示。

**失败示例**

- 只有 `F8` 有效，`Ctrl+F8` 无效。
- 文本输入时仍切换面板。
- 按 `Ctrl+F8` 无反应。
- 按 `Ctrl+F8` 同时触发 `Rewind` 的功能。

**解释**

如果你平时使用 `F8`，请改用 `Ctrl+F8`。不要通过改配置文件绕过测试；设置页重新绑定属于另一条路径。

### AC-033-08 双窗回放期间忽略热键

**为什么验**

历史「本局统计」会打开左右双窗。双窗打开期间如果热键仍然生效，可能隐藏右窗、留下孤立左窗，或重新打开实时面板覆盖回放。

**操作**

1. 打开跑局历史。
2. 选择一局有战斗记录的历史。
3. 点击「本局统计」，确认左右双窗打开。
4. 按一次 `Ctrl+F8`。
5. 再按一次 `Ctrl+F8`。
6. 观察双窗是否保持不变。
7. 点击右窗关闭键，关闭双窗。
8. 再按 `Ctrl+F8`。
9. 观察实时贡献面板是否恢复开关。

**通过标准**

- 双窗打开期间，`Ctrl+F8` 不关闭任何一窗。
- 不出现左窗残留或实时面板覆盖回放。
- 关闭双窗后，`Ctrl+F8` 恢复实时面板开关。
- 右窗关闭键仍能关闭两窗。

**失败示例**

- 双窗中按 `Ctrl+F8` 后右窗消失，只剩左窗。
- 双窗中按 `Ctrl+F8` 后实时面板覆盖回放。
- 关闭双窗后热键失效。

**解释**

双窗期间的热键应被忽略，不是被解绑。关闭双窗后必须恢复。

### AC-033-09 双窗布局与关闭行为

**为什么验**

1.8.1 调整了双窗几何和关闭键。需要确认实际界面符合已确认的布局，而不是只在探针中通过。

**操作**

1. 打开跑局历史。
2. 点击「本局统计」。
3. 观察左右两窗：
   - 左右宽度是否一致。
   - 左右外边距是否大致对称。
   - 左窗是否没有关闭键。
   - 右窗是否有帮助键和关闭键。
4. 点击右窗关闭键。
5. 确认两个窗口同时关闭。
6. 重新打开双窗，按 `Esc`。
7. 确认两个窗口同时关闭。
8. 检查左窗标题和右窗标题是否重复。

**通过标准**

- 左右两窗等宽。
- 左右位置大致对称。
- 左窗没有关闭键。
- 右窗关闭键同时关闭两窗。
- `Esc` 也能关闭两窗。
- 没有重复标题、重叠文字或被截断的按钮。

**失败示例**

- 左右宽度明显不同。
- 左窗仍有 `X`。
- 关闭右窗后左窗仍在。
- 标题重复或内容被遮挡。

**解释**

具体像素会随分辨率变化；判据是等宽、对称、关闭行为一致，不要求固定像素值。

### AC-033-10 宠物吸收与损耗显示

**为什么验**

1.7.0 将宠物 HP 吸收从玩家格挡中拆出，并新增宠物损耗。只有实际界面检查，才能确认数值没有重叠或被旧字段覆盖。

**前置条件**

当前对局或历史中包含奥斯提或瓦皮。没有宠物时记 `N/A`，不要强行构造。

**操作**

1. 使用包含宠物的角色进入战斗。
2. 打出宠物相关卡牌，或让宠物吸收伤害。

4. 查看防御区分节。

6. 如果有碎骨或牺牲击杀奥斯提，检查损耗是否为红色负项。
7. 检查数值是否与相邻行重叠。

**通过标准**

- 宠物吸收和宠物损耗分别显示。
- 宠物吸收不混入玩家格挡。
- 碎骨/牺牲造成的剩余 HP 损耗显示为独立负项。
- 数值没有重叠、截断或负号错误。

**失败示例**

- 宠物吸收仍写入普通格挡。
- 损耗与自伤混在同一行。
- 数值重叠或显示为空。
- 瓦皮也出现宠物损耗。

**解释**

瓦皮只参与吸收，不参与碎骨/牺牲损耗。没有宠物时不能判断该功能，因此允许 `N/A`。

### AC-033-11 愚者旋律名称显示

**为什么验**

第三方本地化模组 `FoolMelodyReplacer` 可能把旋律卡标题替换成 SmartFormat 占位符。1.7.2 已做纯文本转换，需要在实际界面确认。

**前置条件**

当前环境启用愚者内容和 `FoolMelodyReplacer` 0.3.2。没有愚者时记 `N/A`。

**操作**

1. 进入有愚者卡牌的对局或卡牌库。
2. 找到旋律相关卡牌。
3. 检查卡牌名称、战斗贡献面板和历史回放中的名称。
4. 分别检查中文和英文界面至少一处。
5. 观察是否出现 `{MelodyWaText}`、`{MelodyChoText}`、`{MelodyKiText}`、BBCode 标签或空字符串。

**通过标准**

- 中文名称类似 `哇 交响乐`、`啾 就绪`、`哇 叽`。
- 英文名称类似 `Wah Symphony`、`Cho Ready`、`Wah Ki`。
- 没有占位符、BBCode 或空名称。
- 贡献面板与历史回放使用同一名称。

**失败示例**

- 显示 `{MelodyWaText}` 等占位符。
- 显示 `[b]`、`[color]` 等 BBCode 原文。
- 名称为空或内部 ID。

**解释**

这是第三方本地化兼容项。没有安装对应模组或没有愚者内容时，不能判定为失败。

**记录**

```text
AC-033-11：PASS / FAIL / N/A
```

### AC-033-12 历史回放 DPS 与先古名称

**为什么验**

历史回放 DPS 曾经显示横线，先古事件名称曾经显示英文。1.7.3 改为使用 `.run` 回合总数和游戏当前词表。

**操作**

1. 打开跑局历史。
2. 选择一局有战斗回合记录的历史。没有历史时，先正常打一局再回到本项。
3. 打开「本局统计」或回放区域。
4. 查看「每回合平均伤害」。
5. 确认显示数值，而不是 `—` 或空白。
6. 查看先古事件名称。
7. 切换语言，重复检查至少一次。

**通过标准**

- DPS 显示数值。
- DPS 使用历史回合总数，不是实时战斗回合数。
- 先古名称随游戏当前语言显示。
- 中文示例为 `瓦库`、`佩尔`；英文示例为 `Vakuu`、`Pael`。

**失败示例**

- DPS 仍为 `—`。
- DPS 为 `0.0` 但历史中有伤害。
- 中文界面显示 `Vakuu`、`Pael`。
- 先古名称显示内部 ID。

**解释**

本项不要求手工计算 DPS，只要求有数值、名称语言正确、不是旧回归现象。

**记录**

```text
AC-033-12：PASS / FAIL
```

### 4.2 v0.111.1

### AC-033-13 v0.111.1 运行验收

**为什么验**

1.9.0 已用 v0.111.1 程序集构建，但没有在 v0.111.1 游戏内运行。单文件双版本兼容必须至少做一次运行冒烟。

**操作**

1. 关闭 v0.113.1。
2. 按平时的方法切换到 v0.111.1。
3. 启动游戏。
4. 确认 Mod 列表显示 Stats the Spire 1.9.0。
5. 打开 RitsuLib 设置页，确认页面可用。
6. 进入一局短跑局。
7. 完成至少一场战斗。
8. 在战斗中按 `Ctrl+F8`，确认贡献面板可开关。
9. 退出战斗并关闭游戏。
10. 检查贡献数据目录是否写出 `combat_*.json`。
11. 切回 v0.113.1。

贡献数据目录：

```text
%AppData%\sts2_community_stats\contributions\{StartTime}_{seed}\
```

**通过标准**

- 1.9.0 在 v0.111.1 可加载。
- 设置页可打开。
- `Ctrl+F8` 可注册并使用。
- 至少一场战斗写出文件。
- 无启动崩溃、补丁异常或致命日志。
- 不出现同一楼层重复文件。

**失败示例**

- Mod 列表没有 1.9.0。
- 启动崩溃。
- 设置页打不开。
- 战斗后没有任何贡献文件。
- 同一场战斗产生重复文件。

**解释**

v0.111.1 没有愚者角色入口。愚者、宠物和旋律相关项目在 v0.111.1 上不要求覆盖。若你不使用 v0.111.1，可记 `N/A`，但该项保持未验证，不能算通过。

**记录**

```text
AC-033-13：PASS / FAIL / N/A
备注：
```
