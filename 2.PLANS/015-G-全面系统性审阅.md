## 1. 目标

对当前项目做一次独立、全面、系统性的只读审阅。重点回答：

1. 为什么此前的审阅没有发现地图悬停残留。
2. 当前源码、文档、测试、构建、部署与游戏集成有哪些缺陷。
3. 哪些缺陷会影响玩家可见行为、数据正确性、兼容性、安全性或维护性。
4. 每一项缺陷的证据、影响、复现方式、修复建议与优先级。

## 2. 范围

- 需求、SPEC、SDD、ADR、计划、变更日志之间的一致性。
- 71 个 C# 源文件与 19 个补丁类。
- Harmony 补丁目标、执行顺序、异常隔离、版本差异。
- UI 生命周期、节点归属、焦点、关闭、重开、重建、拖拽与缩放。
- 战斗归因、卡牌/遗物/药水/商店/意图统计与生涯统计。
- 同种子对局隔离、存档写入、损坏文件处理、legacy 迁移。
- 设置页、热键、RitsuLib 依赖、本地化。
- v0.111.1 与 v0.113.1 兼容路径。
- 构建、打包、manifest、版本号、部署与双副本冲突。
- 测试方法、证据强度、未验证项、存档副作用。
- 安全、隐私、路径处理、反序列化、日志泄露。
- 性能、分配、每帧工作、缓存失效、资源泄漏。
- 卡牌残影的静态证据与可行的 A/B 方案。

## 3. 方法

- 多个独立子代理按切片只读审阅；每个子代理必须给出文件与行号证据。
- 父会话独立复核关键结论，不直接采信子代理结论。
- 运行当前源码构建、静态扫描、依赖检查与可执行的隔离测试。
- 对动态 UI 问题建立生命周期矩阵，不以“源码看起来会清理”作为通过依据。
- 对无法运行验证的项目，明确标注“源码级结论”或“未验证”。
