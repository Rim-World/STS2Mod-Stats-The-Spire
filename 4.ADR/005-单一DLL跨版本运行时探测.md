# 单一 DLL 跨版本运行时探测

- 状态：已接受
- 日期：2026-11-19
- 项目版本：1.4.1
- 相关文件：`9.SRC/src/UI/CareerStatsSection.cs`、`9.SRC/src/Collection/RunHistoryAnalyzer.cs`、`9.SRC/src/Patches/CombatHistoryPatch.cs`、`9.SRC/src/CommunityStatsMod.cs`

## 背景

游戏 v0.111.1 与 v0.113.1 存在 API 差异：

- `GameMode` 数值不同：v0.111 的 `Custom=3`；v0.113 的 `Dread=3`，另有 `Blitz=4`。
- v0.113 新增愚者角色；v0.111 的 `ModelDb.AllCharacters` 只有 5 个角色。
- `Hook.AfterCardGeneratedForCombat` 在公开源码的旧分支中曾使用 `bool addedByPlayer`；v0.111 与 v0.113 已改为 `(ICombatState, CardModel, Player?)`。
- 商店库存：v0.111 调用 `MerchantRoom.GetLocalInventory()`；v0.113 调用 `RunManager.MerchantSynchronizer.GetLocalInventory()`。
- 旧版源码使用 `STS2_GE_V105` 编译常量切换 API。

用户要求同一个 Mod 文件同时适配 v0.111.1 与 v0.113.1，不构建多个版本。

## 决策

只构建一个 `sts2_statsthespire_local.dll`。跨版本差异使用运行时探测：

- 角色列表读取 `ModelDb.AllCharacters`，不引用愚者类型。
- 模式按 `GameMode.ToString()` 匹配，模式选项读取 `Enum.GetNames<GameMode>()`。
- 可选的 Harmony 钩子读取目标方法的参数数量与类型，再选择 postfix。
- 商店库存通过反射先探测 `MerchantRoom.GetLocalInventory`，再探测 `RunManager.MerchantSynchronizer`。
- 删除 `STS2_GE_V105` 编译期分支。

## 备选方案

- 按游戏版本构建两个 DLL：否决。用户要求单一文件，且会增加发布与测试负担。
- 继续使用 `#if` 编译常量：否决。不同常量生成不同二进制，无法满足单一文件要求。
- 直接引用愚者类型并按版本捕获 `TypeLoadException`：否决。v0.111 加载阶段可能失败，风险高于动态列表。
- 只支持 v0.113.1：否决。用户明确要求同时兼容 v0.111.1。

## 后果

获益：

- 用户只需安装一个 DLL。
- 新增角色和模式可自动出现在界面。
- 版本差异集中在少量探测点，便于维护。

代价：

- 不能依赖编译期检查所有游戏 API。
- 可选补丁必须在运行时验证目标签名。
- 每次游戏更新仍需实机回归。

下游规则：

- 不得新增按版本定义的编译符号。
- 不得在 UI 构建阶段直接引用仅存在于单一版本的角色类型。
- 新增游戏枚举分支时必须按名称匹配，禁止按整数匹配。
- 每次提交前必须分别用 v0.111.1 与 v0.113.1 的 `sts2.dll` 编译一次。
- v0.111.1 实机未验证前，文档不得写「已验证」。
