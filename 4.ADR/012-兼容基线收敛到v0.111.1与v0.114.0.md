# 兼容基线收敛到 v0.111.1 与 v0.114.0

- 状态：已接受
- 日期：2026-11-28
- 当时的项目版本：1.13.1
- 相关文件：`1.PRD/001-项目范围与验收.md`、`6.SPEC/001-总体规范.md`、`5.SDD/001-总体设计.md`、`9.SRC/README.md`、`9.SRC/README_ZH.md`、`9.SRC/README_EN.md`

## 背景

ADR-005 确定了单一 DLL 与运行时探测。ADR-010 将兼容范围扩展到 v0.111.1、v0.113.1 与 v0.114.0，并规定三版本构建。

2026-11-28，用户明确当前只需要兼容 Slay the Spire 2 v0.111.1 与 v0.114.0。v0.113.1 不再作为构建、加载、运行或视觉验收门槛。当前安装的游戏为 v0.114.0；v0.111.1 仍有运行验证缺口。

旧文档、SPEC、README 与 manifest 描述仍写三版本。该口径与用户当前要求不一致，必须收敛。

## 决策

继续使用一个 `sts2_statsthespire_local.dll`。当前目标兼容基线为 v0.111.1 与 v0.114.0。

- 发布前必须完成 v0.111.1 与 v0.114.0 的 Release 构建，并让同一 DLL 在这两个版本加载。
- v0.113.1 的构建、加载和探针结果只保留为历史证据，不作为发布门槛。
- 代码中的 v0.113.1 兼容分支可以保留。本轮不删除这些分支，避免引入不必要的编译与回归风险。
- 下一次发布包的 manifest、README 与适用版本说明必须改为两版本口径。1.13.1 及更早的输出包不改写。
- 当前文档历史记录中的 v0.113.1 验证结果保留，但必须标注为历史。

## 备选方案

- **继续支持 v0.111.1、v0.113.1 与 v0.114.0**：否决。用户已明确当前只需要 111 与 114；继续把 113 作为门槛会增加无效测试与发布负担。
- **只支持 v0.114.0**：否决。用户明确要求继续兼容 v0.111.1。
- **立即删除所有 v0.113.1 兼容代码**：否决。删除会改变运行时探测、补丁注册与构建内容，需要额外回归；保留代码不影响 111 与 114，风险更低。
- **分别构建 111 与 114 两份 DLL**：否决。违反 ADR-005 的单一 DLL 决策，并增加安装与版本不一致风险。

## 后果

获益：

- 验收任务只保留 v0.111.1 与 v0.114.0，减少无效测试。
- 当前游戏 v0.114.0 与旧稳定版 v0.111.1 仍由同一文件支持。
- 历史验证证据不丢失，后续仍可查。

代价：

- v0.113.1 不再获得发布保证；该版本上的后续问题不作为修复门槛。
- 源码仍保留部分 113 分支，文档必须明确这些分支不代表当前支持承诺。
- 当前 1.13.1 输出包与源码 README 的版本说明会短暂不一致；下一次构建统一。

下游规则：

- 新 SPEC 条款以 SP-132 至 SP-136 为准；旧 SP-039、SP-042、SP-045、SP-050、SP-114、SP-115 标记废止。
- 新 PRD 需求以 RQ-036 为准；RQ-002 与 RQ-003 标记废止，历史记录保留。
- 测试报告与计划中涉及 v0.113.1 的未完成项改为「不适用」或「历史」。
- 不得把 v0.113.1 的历史 PASS 写成当前发布验证。
