# 自动出牌按来源牌汇总

- 计划编号：041-M
- 建立时间：2026-11-27 23:29
- 更新时间：2026-11-27 23:29
- 状态：未开始（方案已定；等待施工）
- 目标 Mod 版本：1.11.0
- 需求：RQ-033、AC-032
- 适用游戏：v0.111.1、v0.113.1、v0.114.0
- 相关源码：`9.SRC/src/Patches/CombatHistoryPatch.cs`、`9.SRC/src/Collection/CombatTracker.cs`、`9.SRC/src/Collection/ContributionMap.cs`、`9.SRC/src/Collection/RunContributionAggregator.cs`、`9.SRC/src/Util/ContributionPersistence.cs`、`9.SRC/src/UI/ContributionChart.cs`、`9.SRC/src/Patches/FoolContentPatch.cs`

## 1. 目标

把自动打出的牌产生的出牌次数、伤害、格挡、抽牌、能量、星星、治疗、自伤与宠物数值，汇总到触发这条自动出牌链的来源牌。

首批来源牌：

- 乱战（Mayhem）
- 惊逃（Stampede）
- 傻瓜（Simpleton）

嵌套自动出牌统一归到根来源。手动打出的牌保持独立统计。

## 2. 现状

当前 `CardPlayStarted` 会为自动牌增加它自己的 `TimesPlayed`。直接伤害与格挡由游戏传入自动牌自身，因此记在自动牌名下。乱战和傻瓜的能力上下文可能取得抽牌、能量、修正伤害；惊逃没有上下文。

结果：

- 乱战行通常只有 `x1`。
- 自动打出的牌单独成行。
- 傻瓜可能出现 `SIMPLETON_POWER` 行。
- 无法直接看到“乱战一共打出多少伤害”。

## 3. 统一口径

1. 采用根来源汇总。乱战自动打出 A，A 又自动打出 B，A 和 B 都归乱战。
2. 采用写入层汇总，不只在界面层拼接。
3. 自动牌的直伤、修正伤害、格挡、抽牌、能量、治疗、星星、自伤、宠物数值全部进入根来源桶。
4. 根来源牌自己的手动出牌统计保留。
5. `TimesPlayed` 只表示来源牌自己手动打出的次数。
6. 新增 `AutoPlayedCount` 表示自动打出的牌次数。
7. 自动牌不再生成独立子行；首版不保留自动牌明细子条。
8. 旧对局不追溯重算。

示例：

| 修改前 | 修改后 |
|---|---|
| 乱战 x1，伤害 0 | 乱战 x1 + 自动3，伤害 30 |
| 打击 x2，伤害 20 | 手动打击仍为独立行 |
| 打击 x1，伤害 10（自动） | 不再独立显示 |

## 4. 施工步骤

### 4.1 数据模型

- `ContributionAccum` 增加 `AutoPlayedCount`。
- `MergeFrom` 累加 `AutoPlayedCount`。
- `RunContributionAggregator.MergeMaxFrom` 与 `Clone` 增加该字段。
- `ContributionPersistence.SourceDto`、`ToDto`、`FromDto` 增加该字段；旧 JSON 缺省为 0。
- `ContributionChart` 显示手动次数与自动次数。

### 4.2 自动帧

- `CombatHistoryPatch.AfterCardPlayStarted` 把 `cardPlay.IsAutoPlay` 传给跟踪器。
- `CombatTracker.OnCardPlayStarted` 扩展卡牌上下文栈，记录：
  - 卡牌 ID；
  - 卡牌 hash；
  - 卡牌 origin；
  - 根来源 ID；
  - 根来源类型；
  - 是否自动牌。
- 自动帧开始压栈，`OnCardPlayFinished` 出栈。
- 自动帧内继续嵌套自动牌时继承外层根来源。
- 自动帧内嵌套手动牌时不继承根来源，手动牌按原逻辑记账。
- 战斗结束、回合边界和强制重置时清空自动帧，防止泄漏。

### 4.3 来源解析

- 增加根来源解析：当前自动帧存在时继承根来源；否则按“能力来源 → 遗物来源 → 药水来源 → 当前手动牌”解析。
- 增加显式映射，避免能力行代替卡牌行：
  - `MAYHEM_POWER` → `MAYHEM`
  - `STAMPEDE_POWER` → `STAMPEDE`
  - `SIMPLEON_POWER` → `SIMPLEON`
- 优先使用 `ContributionMap.GetPowerSource` 的真实来源；真实来源缺失时才使用显式映射。
- 没有来源上下文时不强行编造来源，保持原逻辑或 `UNTRACKED`，并写警告日志。

### 4.4 来源上下文补全

- 乱战已有 `MayhemPower.AfterAutoPrePlayPhaseEntered` 上下文。
- 傻瓜已有 `SimpletonPower.AfterAutoPostPlayPhaseEntered` 上下文；补上卡牌映射。
- 惊逃新增 `StampedePower.AfterAutoPostPlayPhaseEntered` 上下文。v0.107、v0.111、v0.113.1、v0.114 都有该方法；运行时仍用 `TryPatch`，缺失时跳过。

### 4.5 写入归因

- 自动帧内的直接伤害、格挡、抽牌、能量、治疗、星星、自伤、宠物数值写入根来源。
- 自动牌的修正伤害、修正格挡、减伤写入根来源；这会减少力量、易伤、虚弱等单独来源行中的自动牌部分。
- 自动牌施加的能力登记为根来源；后续该能力造成的持续伤害继续归到根来源。
- 自动牌生成的牌登记为根来源。
- 自动牌的费用节省仍跳过，不产生虚假能量节省。
- 手动牌、非自动牌和没有自动帧的调用保持原有优先级。

### 4.6 不计入重复

- 自动牌不增加自己的 `TimesPlayed`，只增加根来源 `AutoPlayedCount`。
- 自动牌不创建独立贡献桶，避免父行与子行同时出现。
- `DirectDamage` 与 `ModifierDamage` 仍是总伤害的互斥拆分。
- 同一笔伤害只写入一次。
- 手动出牌和自动出牌分开写入；同名卡不会把自动部分与手动部分混在一起。

## 5. 验证计划

### 5.1 构建

- v0.111.1、v0.113.1、v0.114.0 Release 构建均为 0 错误。
- 自动帧新增字段不改变单一 DLL 形态。

### 5.2 定向战斗

1. 乱战自动打出攻击牌：乱战行出现自动次数与直接伤害，自动牌不出现在来源列表。
2. 惊逃自动打出攻击牌：结果同上。
3. 傻瓜自动打出最低费牌：来源名为「傻瓜」，不是 `SIMPLEON_POWER`。
4. 嵌套：乱战 → 某牌 → 再自动打出攻击牌；两次自动出牌都归乱战。
5. 同一张牌手动打出一次、自动打出一次：手动行保留，自动部分归来源牌。
6. 自动牌造成格挡、抽牌、能量、治疗、星星：全部归来源牌。
7. 自动牌施加力量后，后续攻击的修正伤害归来源牌。
8. 自动牌后接手动牌：手动牌不继承自动来源。
9. 保存、退出、重载：`AutoPlayedCount` 与汇总数值保持。
10. v0.111.1 与 v0.114.0 各跑一次加载和定向战斗。

### 5.3 数据核对

- 战斗 JSON 中来源牌行包含汇总值。
- 自动牌子行不出现。
- `UNTRACKED` 不因目标三张牌增加。
- 总量与实际扣血、格挡、抽牌、能量一致。
- 旧 JSON 读取不报错，`AutoPlayedCount` 默认为 0。

## 6. 风险

- 修正伤害归属改变：力量、易伤等单独来源行会减少自动牌部分。这是全量汇总的必然结果。
- 来源上下文缺失：没有上下文的自动效果不能强行归属；保持原逻辑并记录。
- 自动帧泄漏：`CardPlayFinished` 缺失、战斗结束或异常路径必须清理。
- 傻瓜映射：必须验证不再出现独立的 `SIMPLEON_POWER` 行。
- 惊逃旧版本：方法存在，但仍需三版本加载验证。
- 旧记录：不追溯；同一份生涯统计中可能同时存在旧分行记录与新汇总记录。
