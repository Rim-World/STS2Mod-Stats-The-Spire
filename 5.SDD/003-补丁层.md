# 补丁层

- 版本：1.6.0（施工目标；当前代码基线 1.5.2）
- 更新时间：2026-11-21 19:32
- 关联组件：`src/Patches/`、`src/Util/SafePatching.cs`

## 组件职责

补丁层把游戏事件转换为采集调用。它只负责“何时调用哪个采集方法”，不负责统计规则和 UI。

| 补丁组 | 代表符号 | 触发 |
|---|---|---|
| 运行生命周期 | `RunLifecyclePatch` | 新建/继续单人、多人游戏 |
| 战斗生命周期 | `CombatLifecyclePatch` | 战斗开始、回合、结束 |
| 战斗历史 | `CombatHistoryPatch` | 伤害、格挡、能力、遗物、药水事件 |
| 卡牌 | `CardLibraryPatch`、`CardRewardScreenPatch` | 卡牌奖励界面隐藏贡献面板 |
| 遗物 | `RelicLibraryPatch`、`RelicHookContextPatcher` | 遗物触发与上下文 |
| 能力 | `PowerHookContextPatcher`、`PaleBlueDotPowerContextPatch` | 能力施加与触发；暗淡蓝点专用来源 |
| 地图与商店 | `MapPointPatch`、`ShopPatch` | 地图节点、商店库存与价格 |
| 意图 | `IntentHoverPatch`、`EnemyDamageIntentPatch` | 悬停、意图伤害 |
| 统计页 | `StatsScreenTabPatch`、`RunHistoryPatch` | 百科大全与历史页 |
| 兼容补丁 | `FiddleDrawCompatPatch`、`VoidFormEnergyCostPatch` | 有效目标存在时保留归因 |
| 兼容补丁 | `PaleBlueDotPowerContextPatch` | 在异步施加 `DrawCardsNextTurnPower` 前捕获「暗淡蓝点」来源 |

## 依赖

允许：

- `Patches -> Collection`：调用采集方法。
- `Patches -> Config/Util`：读取设置、异常隔离、名称映射。
- `Patches -> Godot`：读取节点状态，但不得构造完整面板。

禁止：

- `Patches` 不得直接实现统计聚合。
- `Patches` 不得写文件；持久化由 `Collection`/`Util` 负责。
- `Patches` 不得在补丁方法中阻塞等待；异步操作必须交给后台任务。

静态检查：

```bash
rg -n "File\.|Directory\." 9.SRC/src/Patches
rg -n "Thread\.Sleep|\.Wait\(|\.Result" 9.SRC/src/Patches
```

## 地图悬停面板生命周期

`MapPointPatch` 在 `NMapPoint.OnFocus` 创建商店价格或未知房间面板。面板必须登记到内部 `ConditionalWeakTable`，并在以下时机统一调用 `HideAllHoverPanels()`：

- `NMapScreen.Close` 后置补丁。
- `NMapScreen.CleanUp` 后置补丁。
- `NMapScreen.Open` 前置补丁。
- `NMapScreen.SetMap` 前置补丁。

不得只依赖 `NMapPoint.OnUnfocus`。`NMapScreen.Close` 只隐藏地图，不保证对地图点触发失焦。

## 补丁注册

`CommunityStatsMod.Initialize` 遍历程序集类型，对每个类型调用 `Harmony.CreateClassProcessor(...).Patch()`，单个类型失败只记录警告。之后逐组调用手工补丁，每组独立 try/catch：

- `RelicHookContextPatcher.PatchAll`
- `PowerHookContextPatcher.PatchAll`
- `OrbPassivePatch.PatchOrbTurnEndTriggers`
- `OrbEvokePatch.PatchOrbEvokeMethods`
- `KillingBlowPatcher.PatchAll`
- `CardGenerationOriginPatch.Patch`
- `PatchInventory.Log`
- `RunLifecyclePatch.RegisterMetricsHook`

手工补丁安装完成后才调用 `MonsterIntentMetadata.Initialize`，避免 ModelDb 未就绪时把空结果写入缓存。

对局结束时，`RunLifecyclePatch.AfterCreateRunHistoryEntry`（`RunHistoryUtilities.CreateRunHistoryEntry` 的 Postfix）对胜利、失败与放弃结局统一调用 `RunDataCollector.OnMetricsUpload`。`RunDataCollector` 用 `RunKey` 记录已收尾对局；重复调用直接返回。v0.111.1 由该 Postfix 完成收尾；v0.113.1 的 Postfix 先完成收尾，随后到达的事件路径被去重。

## 目标探测

- 属性补丁使用 `[HarmonyPatch(typeof(X), nameof(X.Y))]`，编译期检查符号。
- 方法名可能随游戏版本变化时，使用 `AccessTools.DeclaredMethod` 或 `AccessTools.TypeByName` 探测。
- `Safe.TryPatchFirst` 在目标缺失时记录 `[StatsTheSpire]` 警告并返回，不抛出。
- `Safe.TryPatchFirst` 依次尝试多个方法名，用于游戏版本改名（如 `JugglingPower`、`Pendulum`、`ToastyMittens`）。
- `HarmonyPrepare` 对可选补丁返回 `TargetMethod() != null`。

## 失败隔离

- 每个补丁入口包裹 `Safe.Run`。
- `Safe.RunAsync` 捕获异步异常。
- `Safe` 使用游戏 `Log.Warn`，不写独立日志文件。
- 单个补丁失败不得影响其他补丁注册；每个手工补丁组独立隔离。
- `PatchInventory.Log` 必须输出本 Mod 的绑定目标与数量。

## 1.6.0 目标设计（未实现）

本节是 1.6.0 的施工设计目标，当前 1.5.2 尚未实现。对应任务见 `2.PLANS/018-G-1.6.0-战斗归因修复与愚者覆盖.md`。

### 补丁注册

- 新类型仍使用 `AccessTools.TypeByName`、字符串目标名或 `Safe.TryPatchFirst`。
- v0.113.1 新类型在 v0.111.1 不存在时，目标探测返回 null；补丁记录跳过，不抛出。
- 属性补丁只能用于两版都存在的类型；新内容必须走手工可选注册。
- `PatchInventory.Log` 继续输出实际绑定目标与数量，新增目标必须能被清点。

### 真实伤害守卫

- 目标为 `CreatureCmd.Damage` 的实际根重载，而不是只绑定 7 参数重载。
- 嵌套调用使用异步上下文深度计数；守卫只在最外层记账，或按每个目标记账一次。
- 7 参数重载在 v0.111.1 继续保留；两条路径不得重复。

### 来源上下文

- 能力/遗物 hook 使用保存-恢复栈，而不是单槽覆盖。
- 进入 hook 时保存当前来源，退出时恢复外层来源；异常路径也必须恢复。
- 预览调用与真实伤害使用不同上下文；预览不得写入真实账。
- 未登记来源不得自动记到当前卡牌；无法判定时保留未归因。

### 待定抽牌

- 只对实际会抽牌的 hook 设置待定来源。
- 来源在抽牌消费、hook 结束、回合边界或战斗边界清理。
- 下一次非手抽牌不得继承上一次来源。
