# 恢复 90 天清理、RitsuLib 开关与当前存档保护

- 时间：2026-11-25 04:21
- 适用 Mod：1.9.3
- 游戏基准：v0.111.1（运行）；v0.113.1（Release 构建）
- 关联需求：RQ-030
- 关联计划：`2.PLANS/036-S-恢复90天清理与设置开关.md`
- 结论：1.9.3 恢复默认 90 天清理；RitsuLib 设置提供开关；当前单人/多人存档引用的对局受保护。1.5.2 删除自动清理是错误施工。

## 1. 需求与更正

用户 `1.PRD/用户prompt/0010.md` 明确要求保留原版删除行为。1.5.1 的计划 `009-S` 与 SPEC 2.0 都按该要求实现。1.5.2 的计划 `016-G` 将 T-03-05 改成“删除启动期 90 天自动清理”；该改动与用户要求相反，已在该计划顶部标注为错误施工。

1.9.3 恢复清理，并增加两个约束：

1. 默认开启，用户可在 RitsuLib 设置页关闭。
2. 当前存档引用的对局不得删除。

## 2. 实现

### 清理策略

`ContributionRetention` 在启动时等待 `SaveManager` profile 初始化，然后：

- 删除 `contributions/` 顶层超过 90 天的 legacy `.json` 文件。
- 删除 `contributions/` 顶层超过 90 天的 Run 目录。
- 跳过 `current_run.save`、`current_run.save.backup`、`current_run_mp.save`、`current_run_mp.save.backup` 引用的 StartTime 与 seed。
- 存档读取失败时跳过清理。
- 跳过 reparse point。
- 单文件或目录失败只写日志，不阻断启动。

### 设置

- `ModConfig.AutoCleanupEnabled` 默认 `true`。
- 持久化键：`mod_prefs.json` 的 `auto_cleanup`。
- RitsuLib 设置页新增「自动清理 90 天前的贡献数据（下次启动生效）」。
- 关闭后启动不扫描、不删除贡献数据。

### 启动

`CommunityStatsMod.Initialize` 调用 `ContributionRetention.ScheduleStartupPrune()`。清理在 profile 初始化后执行；profile 60 秒内未就绪则跳过，避免在没有当前存档信息时误删。

- RitsuLib 开关的图形界面未人工视觉检查；探针读取了设置页条目与绑定值。
- 实际启动清理删除了 57 个过期贡献文件；清理前备份位于 `TMP/1.9.3/contributions-before-cleanup/`。当前数据为 320 个条目。
