# 自动出牌按根来源汇总

- 状态：已接受
- 日期：2026-11-27
- 当时的项目版本：1.11.0（目标）
- 相关文件：`9.SRC/src/Patches/CombatHistoryPatch.cs`、`9.SRC/src/Collection/CombatTracker.cs`、`9.SRC/src/Collection/ContributionMap.cs`、`9.SRC/src/Collection/RunContributionAggregator.cs`、`9.SRC/src/Util/ContributionPersistence.cs`、`9.SRC/src/UI/ContributionChart.cs`、`9.SRC/src/Patches/FoolContentPatch.cs`、`1.PRD/001-项目范围与验收.md`、`2.PLANS/041-M-自动出牌按来源牌汇总.md`、`6.SPEC/001-总体规范.md`

## 背景

当前自动打出的牌由 `CardPlayStarted` 增加自己的 `TimesPlayed`。直接伤害与格挡携带自动牌自身的卡牌来源，所以记在自动牌名下；乱战与傻瓜的能力上下文可能取得抽牌、能量与修正伤害，惊逃没有来源上下文。

这产生三个问题：

- 来源牌行无法看到它触发的自动牌总伤害。
- 同一套自动链会分裂成来源牌行、自动牌行与能力行。
- 傻瓜可能显示 `SIMPLETON_POWER`，而不是「傻瓜」卡。

用户要求把自动打出的攻防数值汇总到乱战、惊逃、傻瓜来源牌。

## 决策

采用“根来源 + 写入层汇总”：

1. 一次自动出牌从开始到结束建立自动帧。
2. 第一条自动出牌链的来源牌是根来源；嵌套自动继续继承根来源。
3. 自动帧内的出牌次数、伤害、格挡、抽牌、能量、星星、治疗、自伤与宠物数值写入根来源桶。
4. `TimesPlayed` 只表示来源牌自己的手动出牌次数；新增 `AutoPlayedCount` 表示自动打出的牌次数。
5. 自动帧内嵌套的手动牌不继承根来源；同名卡的手动与自动统计分开。
6. 自动牌不再生成独立行；首版不保留自动牌明细子条。
7. 旧 JSON 不追溯重算，`AutoPlayedCount` 缺失时按 0 读取。

来源映射优先使用真实能力来源；缺失时使用显式表：

- `MAYHEM_POWER` → `MAYHEM`
- `STAMPEDE_POWER` → `STAMPEDE`
- `SIMPLETON_POWER` → `SIMPLEON`

## 备选方案

- **只在界面层按名称合并**：否决。无法区分同一张牌的手动与自动部分，旧 JSON 仍是分裂数据，合并时容易重复计数。
- **按直接父牌汇总**：否决。乱战 → A → B 时 B 会归 A，乱战拿不到完整链条，仍会出现多层来源。
- **只汇总直接伤害**：否决。用户要求攻防数值全部汇总；只汇总直伤会留下修正伤害、格挡与资源行，仍然分裂。
- **保留自动牌子行并同时写入来源牌**：否决。父子同时持有同一数值，会重复统计。

## 后果

- 来源牌行显示完整自动链数值；自动牌子行消失。
- 力量、易伤、虚弱等修正来源行会减少自动牌部分。这是全量汇总的代价。
- 手动牌统计不变；手动与自动同名牌不再混合。
- 持久化、汇总、UI 与测试都需要新增 `AutoPlayedCount`。
- 没有来源上下文的自动效果不能强行归属；保持原逻辑或 `UNTRACKED`。
- 目标版本为 1.11.0；旧对局保持旧口径。
