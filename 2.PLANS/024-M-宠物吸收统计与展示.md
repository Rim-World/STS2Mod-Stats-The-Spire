## 1. 目标

新增独立字段 `PetAbsorbed` 和 `PetWasted`，分别统计宠物吸收的伤害与主动击杀宠物浪费的 HP，并在现有防御区同时展示奥斯提与瓦皮。

完成后的行为：

1. 奥斯提的吸收量从 `EffectiveBlock` 移入 `PetAbsorbed`。
2. 瓦皮实际失去的生命值记入 `PetAbsorbed`。
3. 两种宠物使用同一来源类型、同一颜色、同一防御区、同一百分比口径。
4. 碎骨或牺牲主动击杀奥斯提时，剩余 HP 记入 `PetWasted`。
5. `EffectiveBlock` 只表示真实格挡。
6. 旧对局数据中的奥斯提吸收迁移到 `PetAbsorbed`，不重复计入。
7. 旧对局中可识别的负 `EffectiveBlock` 迁移到 `PetWasted`，总防御不变。
8. 瓦皮不能主动击杀，不产生 `PetWasted`。

## 2. 背景

当前代码把奥斯提 HP 吸收写入 `EffectiveBlock`。该字段的定义是“被格挡吸收的伤害”。瓦皮承受敌方攻击后，伤害被直接排除，没有防御记录。

用户已批准新增独立字段 `PetAbsorbed`。用户随后选择 D，要求把主动击杀宠物浪费的剩余 HP 单独记为 `PetWasted`。

理由是数据层需要区分：

- 格挡消耗：玩家格挡点数被消耗。
- 宠物 HP 吸收：宠物实际失去生命值，替玩家挡住伤害。
- 宠物 HP 损耗：玩家主动杀死宠物，剩余 HP 没有挡住伤害。

三者可以在同一个“防御”界面展示，但不得在存储层失去区别。

## 3. 范围

### 3.1 数据模型

- 在 `ContributionAccum` 增加 `PetAbsorbed` 和 `PetWasted`。
- `PetWasted` 是非负整数，单位是 HP；表示主动击杀宠物浪费的剩余 HP。
- `TotalDefense` 增加 `PetAbsorbed`，减去 `PetWasted`。
- `MergeFrom` 合并 `PetAbsorbed` 和 `PetWasted`。
- 所有构造、复制、克隆路径包含两个字段。

### 3.2 奥斯提

- `CombatHistoryPatch` 检测奥斯提承伤后传入宠物承伤标记。
- `CombatTracker.OnOstyAbsorbedDamage` 改为写 `PetAbsorbed`。
- 继续使用现有 LIFO 召唤来源栈；召唤卡作为 `OSTY` 子条。
- HP 栈不足时，余量记到 `OSTY` 父条。
- 主动击杀只有 `BONE_SHARDS` 和 `SACRIFICE` 两张牌。
- 两张牌击杀奥斯提时，剩余 HP 立即记入击杀卡的 `PetWasted`。
- 删除 `_pendingOstyDeathDefense` 延迟扣减，不再从 `EffectiveBlock` 扣除。
- 玩家死亡清理奥斯提时，不记录 `PetWasted`。
- 新增主动击杀宠物的卡牌必须加入允许名单，并补测试。

### 3.3 瓦皮

- 用运行时类型名或安全反射识别 `receiver.Monster` 为瓦皮，禁止在 v0.111.1 路径直接引用 v0.113 才存在的 `Wuppy` 类型。
- 仅当 `receiver.PetOwner` 是本地玩家时统计。
- 取宠物承伤 `DamageResult.TotalDamage`，即实际失去的 HP；不得取 `IntendedHpLoss`，不得计 `OverkillDamage`。
- 直接记到 `WUPPY` 父条；不按当前卡牌或能力上下文归因。
- 瓦皮死亡、当前 HP 为 0 或未触发忠诚重定向时，不产生记录。
- 不统计瓦皮被治疗、休息恢复或遗物显示的生命值。
- 玩家不能主动杀死瓦皮；瓦皮不产生 `PetWasted`。

### 3.4 通用宠物过滤

- 奥斯提与瓦皮都使用 `receiver.PetOwner` 和 `IsLocalPlayer` 判断本地归属。
- 队友宠物承伤不得进入本地统计。
- 保留敌方对敌人、敌方对非本地宠物的排除路径。

### 3.5 持久化与汇总

- `ContributionPersistence.SourceDto` 增加 `PetAbsorbed` 和 `PetWasted`。
- `ToDto`、`FromDto`、`SaveCombat`、`SaveSummary`、`LoadSummary`、`BuildMerged` 全部包含两个字段。
- `RunContributionAggregator` 的内存累计、每场快照、磁盘合并和克隆全部包含两个字段。
- 旧 JSON 缺少 `PetAbsorbed` 或 `PetWasted` 时按 0 读取。
- 旧奥斯提数据（`SourceType == "osty"` 或 `OriginSourceId == "OSTY"`）在读取时把 `EffectiveBlock` 迁移到 `PetAbsorbed`，并把旧字段清零，避免双计。
- 旧 JSON 中 `PetWasted` 为 0 且 `EffectiveBlock < 0` 时，把负值绝对值迁入 `PetWasted`，并把 `EffectiveBlock` 设为 0；总防御不变。
- 旧 JSON 中 `EffectiveBlock >= 0` 时，不拆分已相抵的旧值。
- 迁移必须幂等；重复加载不得重复迁移。

### 3.6 界面

- `OSTY` 与 `WUPPY` 使用统一来源类型 `pet`。
- 两行都放入现有“防御”区，前缀使用 `[宠]`。
- 奥斯提保留召唤卡子条；瓦皮只有父条。
- `PetAbsorbed` 使用宠物色；防御总量和百分比包含该字段。
- `PetWasted` 使用独立红色负项，标签为“宠物损耗”；界面显示 `-N`，来源显示击杀卡名称。
- `PetWasted` 与 `SelfDamage` 分开显示，不得把宠物损耗叫作自伤。
- `PetWasted` 不进入正向防御百分比的分母，只从防御总量扣除。
- 旧数据中的 `osty` 类型必须兼容读取；读取时归一化为 `pet`，保存时写 `pet`。
- `SourceId` 保留 `OSTY`；显示名仍从 `OSTY` 查询为“奥斯提”。旧类型只影响分类、颜色和前缀，不改变来源名称。
- 奥斯提显示名改为本地化“奥斯提”；瓦皮显示名改为本地化“瓦皮”。
- 帮助面板增加“宠物吸收”定义：宠物实际失去的生命值，不含溢出伤害。
- 更新 `contrib.help_block`，不得继续把宠物吸收描述成格挡。

- v0.113.1 与 v0.111.1 均可加载。
- v0.111.1 没有瓦皮时，不出现类型加载异常；奥斯提仍可统计。

### 3.8 奥斯提死亡剩余 HP：采用 D

用户已选择 D：新增 `PetWasted` 字段。决策记录在 `4.ADR/008-宠物损耗使用独立字段.md`。

当前实现：

- 奥斯提死亡时，读取剩余 HP。
- 下一位敌人攻击玩家时，从击杀卡（例如碎骨）的 `EffectiveBlock` 扣除这笔剩余 HP。
- 代码位置：`9.SRC/src/Collection/CombatTracker.cs:695`、`:1608`。

实现 D 后：

1. `PetWasted` 记录奥斯提被主动击杀时的剩余 HP。
2. 只有 `BONE_SHARDS` 和 `SACRIFICE` 可以触发。
3. 写入发生在击杀时，不再延迟到下一次敌人攻击。
4. `EffectiveBlock` 不再扣除这笔 HP。
5. `TotalDefense` 减去 `PetWasted`。
6. 瓦皮不能主动击杀，不产生 `PetWasted`。
7. 玩家死亡清理奥斯提时，不产生 `PetWasted`。

**示例：碎骨获得 10 点格挡，奥斯提剩 1 点 HP**

| 时点 | 游戏内 | 当前统计 | D 统计 |
|---|---|---|---|
| 碎骨打出 | 获得 10 点格挡 | 0（未消耗） | 0（未消耗） |
| 碎骨杀死奥斯提 | 剩余 1 HP 消失 | 记下待扣 1 | `PetWasted = 1` |
| 下一次敌人攻击 | 10 点格挡被消耗 | 扣除 1，记 10 | 记 10 点格挡 |
| 结算后 | 实际格挡 10 | 9 | 格挡 10，宠物损耗 1 |

D 的界面结果：碎骨的有效格挡是 10；防御区另有“宠物损耗 −1”。两者不再混在同一个字段。

旧 JSON 中：

- 负 `EffectiveBlock` 迁入 `PetWasted`，总防御不变。
- 已与正格挡相抵的旧值无法还原，保留原值。
- 新版本不再生成新的负 `EffectiveBlock`。

## 6. 验收

- `PetAbsorbed` 和 `PetWasted` 出现在战斗 JSON、summary JSON 和 live JSON。
- 旧 JSON 读取后，奥斯提吸收进入 `PetAbsorbed`，`EffectiveBlock` 不保留同一笔数值。
- 旧 JSON 的负 `EffectiveBlock` 迁入 `PetWasted`；总防御不变。
- 奥斯提吸入之和等于其实际 HP 损失；LIFO 来源与召唤卡对应。
- 瓦皮吸入之和等于其实际 HP 损失；玩家 HP 不因该次攻击减少。
- 碎骨和牺牲主动击杀奥斯提时，剩余 HP 进入 `PetWasted`。
- 玩家死亡清理奥斯提时，不产生 `PetWasted`。
- 瓦皮不产生 `PetWasted`。
- 溢出伤害不计入；瓦皮死亡后不新增吸收。
- 队友宠物承伤不计入本地。
- 防御总量 = 真实格挡 + 宠物吸收 + 其他防御项 - 自伤 - 宠物损耗。
- 旧对局总防御与迁移前一致，不出现双计。
- v0.113.1 与 v0.111.1 Release 构建 0 错误。
- v0.111.1 加载无 `Wuppy` 类型异常。
- 面板显示 `[宠] 奥斯提` 和 `[宠] 瓦皮`，同一防御区和百分比。
- 面板显示独立“宠物损耗”负项，来源为碎骨或牺牲。

## 8. 风险与回滚

| 风险 | 处理 |
|---|---|
| v0.111.1 直接引用 `Wuppy` 类型 | 使用运行时类型名或缓存反射；构建后做 v111 加载探针 |
| 旧数据迁移双计 | 迁移前备份样本；迁移幂等；总防御回归对比 |
| `EffectiveBlock` 与 `PetAbsorbed` 加总错误 | 用固定样本手算；覆盖 JSON、live、summary 三层 |
| `PetWasted` 误记到普通卡或瓦皮 | 只允许 `BONE_SHARDS`、`SACRIFICE`；玩家死亡清理不记录 |
| `PetWasted` 与自伤混显 | 使用独立负项和独立标签；覆盖 T-14 |
| 旧负值迁移双计 | 只在 `PetWasted == 0` 且 `EffectiveBlock < 0` 时迁移；总防御回归 |
| 瓦皮死亡后仍被统计 | 检查 `PetOwner`、`IsAlive`、当前 HP 和重定向结果 |
| 多人远程宠物污染 | 统一本地 `PetOwner` 过滤 |
| 面板出现两套重复宠物区 | 只保留防御区一套父行/子行 |

回滚：

- 保留 1.6.1 源码和 DLL。
- 数据迁移只在新字段上操作；旧 JSON 原文件不覆盖。
- 若 UI 异常，可先关闭宠物行显示，不回滚已写入的 `PetAbsorbed` 数据。
- 若 `PetWasted` 记录异常，可临时隐藏损耗行；不得回滚为负 `EffectiveBlock`。
