# 总体规范

- 版本：3.4
- 适用版本：Mod 1.7.0；兼容 Slay the Spire 2 v0.111.1 与 v0.113.1
- 更新时间：2026-11-22 08:30

## 1. 安装与清单

**SP-001** Mod 目录必须包含 `manifest.json` 与 `sts2_statsthespire_local.dll`。

**SP-002** `manifest.json` 的 `id` 必须为 `sts2_statsthespire_local`。

**SP-003** `manifest.json` 的 `version` 必须为 `1.7.0`。

**SP-004** `manifest.json` 的 `has_pck` 必须为 `false`，`affects_gameplay` 必须为 `false`。

**SP-005** Mod 不得包含 `.deps.json` 文件。

**SP-006** DLL 文件名必须为 `sts2_statsthespire_local.dll`。

## 2. 网络与隐私

**SP-007** 本地版不得发起任何 HTTP 或 HTTPS 请求。

**SP-008** 本地版不得包含服务器地址、上传开关、自动更新检查或离线上传队列。

**SP-009** Mod 不得采集或上传可识别用户身份的信息。

注记（非规范性）：SP-007 至 SP-009 约束本 Mod 代码。硬依赖 RitsuLib 自身可能发送遥测，不属于本 Mod 代码；玩家可在 RitsuLib 设置中管理。

## 3. 数据与设置

**SP-010** 用户数据目录必须为 `%AppData%/sts2_community_stats`。

**SP-011** 用户设置必须写入 `%AppData%/sts2_community_stats/mod_prefs.json`。

**SP-012** 贡献数据必须写入 `%AppData%/sts2_community_stats/contributions/`。

**SP-013** Mod 不得写入游戏安装目录、游戏存档目录或 Steam 云存档目录。

**SP-014** 设置文件缺失时，Mod 必须使用内置默认值。

**SP-015** 设置文件中的未知键必须被忽略，不得导致加载失败。

**SP-016** 设置文件损坏时，Mod 必须记录警告并使用默认值。

**SP-017** 旧版设置中的 `language`、`feature_toggles`、`panel_position`、`use_my_data_only` 必须继续被读取。

**SP-018** 新增设置键必须向后兼容；旧文件缺少键时使用默认值。

## 4. 设置项

**SP-019** 设置必须支持 `language`，值为 `CN` 或 `EN`。

**SP-020** 设置必须支持 `feature_toggles`，其中包含 `ContributionPanel`、`CardLibraryStats`、`RelicStats`、`UnknownRoomOdds`、`ShopPrices`、`IntentStateMachine`、`PotionOdds`、`CardDropOdds`。

**SP-021** 设置必须支持 `panel_position`，包含 `x` 与 `y`。

**SP-022** 设置必须支持 `panel_size`，包含 `width` 与 `height`；宽度与高度必须为正数。

**SP-023** 设置必须支持 `intent_panel_scale`，有效范围必须为 `0.5` 至 `1.25`。

**SP-024** 设置必须支持 `use_my_data_only`，值为布尔值。

## 5. 界面行为

**SP-025** 贡献面板必须由可重绑定热键切换；默认绑定必须为 `F8`，绑定必须持久化到 `mod_prefs.json`；加载时缺失或非法必须回退为 `F8`，设置页交互中非法绑定必须被拒绝并保留原绑定。

**SP-026** 设置必须通过 RitsuLib 的模组设置入口提供；不得由 F7 自绘设置面板提供。

**SP-027** 战斗结束后，贡献面板必须自动显示本场数据。

**SP-028** 贡献面板必须支持拖动改变大小，并在设置保存后保持尺寸。

**SP-029** 生涯统计必须支持对局模式筛选：全部、标准、每日、多人，以及当前游戏版本提供的自定义、恐惧、极速模式。

**SP-030** 生涯统计必须显示平均用时、平均卡组大小、平均遗物数、平均卡牌类型与平均稀有度。

**SP-031** 意图状态机面板必须在生物失焦、死亡或战斗结束时隐藏。

**SP-067** 地图悬停信息面板必须在地图关闭、地图清理、重新打开地图或更换地图时删除；不得显示上一次悬停产生的商店价格面板或未知房间概率面板；对应地图点的面板标记必须同时删除。

## 6. 稳定性与日志

**SP-032** 单个 Harmony 补丁目标缺失时，Mod 必须记录警告并继续加载其他补丁。

**SP-033** 单个补丁回调抛出异常时，Mod 不得让异常传播到游戏主循环。

**SP-034** Mod 日志必须包含固定前缀 `[StatsTheSpire]`。

**SP-035** 统计缓存损坏时，Mod 必须重建或返回空数据，不得崩溃。

**SP-036** 图标或纹理加载失败时，界面必须降级为文本或空图标，不得崩溃。

## 7. 兼容与构建

**SP-037** 源码必须使用 `net9.0` 目标框架。

**SP-038** 源码必须通过 `STS2GameDir` 属性引用游戏程序集，不得把游戏 DLL 提交进仓库。

**SP-039** v0.113.1 构建的错误数必须为 0。

**SP-040** 构建输出必须与 `manifest.json` 位于同一目录。

**SP-041** Mod 的版本号必须在 `manifest.json`、`ModConfig.ModVersion`、源码 `CHANGELOG.md` 与版本日志中一致。

**SP-042** 必须只构建一个 `sts2_statsthespire_local.dll`，同一文件必须能在 v0.111.1 与 v0.113.1 加载；不得生成按游戏版本区分的第二份 DLL。

## 8. 性能

**SP-043** Mod 初始化不得阻塞游戏主线程超过 2 秒。

**SP-044** RunHistory 全量分析必须在后台任务执行，不得在 UI 帧回调中执行。

## 9. 兼容范围

**SP-045** 本版本的目标兼容基线为 Slay the Spire 2 v0.111.1 与 v0.113.1。

**SP-046** 本版本不承诺与原 Workshop 包同时安装时的行为。

**SP-047** 生涯角色筛选必须包含当前游戏 `ModelDb.AllCharacters` 暴露的全部可玩角色；v0.113 必须包含「愚者」。

**SP-048** 角色筛选必须按本地玩家的角色统计；不得因其他玩家使用该角色而把多人对局计入。

**SP-049** 对局模式必须按 `GameMode` 名称匹配；不得按枚举整数值匹配。

**SP-050** 源码必须同时通过 v0.111.1 与 v0.113.1 的 `sts2.dll` 编译；不得只验证一个版本。

## 10. 设置与依赖

**SP-051** 设置页必须在主菜单、跑局暂停和战斗暂停可用。

**SP-052** Mod 必须将 `STS2-RitsuLib` 声明为硬依赖；不得依赖 BaseLib。

## 11. 对局数据身份

**SP-053** 对局数据必须按 `StartTime` 与 seed 组成的 RunKey 隔离；同 seed 的不同对局不得共享 live、商店或汇总文件。

**SP-054** 新局不得加载同 seed 的旧运行态或商店数据；续局只能加载当前 RunKey 的数据。1.4.4 及更早存档没有新目录时，可以只读回退到 legacy seed 数据。

**SP-055** 历史回放必须使用 `RunHistory.StartTime` 定位对局数据；不得只按 seed 定位。

**SP-056** Mod 不得使用 RitsuLib `RunSavedData` 或任何写入游戏存档的机制。

**SP-057** 旧版 `{seed}_*.json` 可以只读回退；Mod 不得自动删除、移动或改名旧版文件；启动与退出流程不得清理贡献数据。

**SP-058** 设置文件损坏时，Mod 必须将警告写入游戏日志；不得使用阻塞式弹窗。

**SP-059** `manifest.json` 的 `min_game_version` 必须为 `0.111.1`。

**SP-060** 续局从 legacy seed 文件加载的商店购买必须复制到当前 RunKey 的 `shop_purchases.json`；不得移动或删除 legacy 文件；空列表不得创建文件。

**SP-068** 暗淡蓝点施加的下回合额外出牌数必须归到「暗淡蓝点」；不得归到触发第 5 张牌；升级版必须按实际数量记录，且每回合最多触发一次。

**SP-069** `Fiddle` 与 `VoidFormPower` 的归因补丁必须保留并绑定；无消费者的记录补丁与空 `PowerReceived` hook 不得保留；Mod 必须把实际绑定目标写入运行日志。

**SP-070** 跑局历史弹窗必须在 `NRunHistory` 子菜单隐藏时关闭；Esc 必须只关闭弹窗；贡献面板必须在退局、放弃、保存退出和新局时隐藏并清除回放数据；战败请求发生时必须隐藏意图面板。

**SP-071** `live.json` 写入必须按不超过 1 秒的防抖合并；战斗结束与保存退出必须强制 flush；JSON 写入必须使用临时文件原子替换；损坏 JSON 必须移动到 `.corrupt-*` 备用，不得被空数据静默覆盖。

**SP-072** 生成卡与原生卡的同名来源必须按来源和生成者分开保存，不得在汇总时相加为翻倍条目；Boss 房白兽雕像必须显示 100%；路径购买必须优先使用商店购买边车；职业缓存必须保留死亡来源；放弃局必须显示 `ABANDONED`；角色筛选不得缩小全局卡牌与遗物 bundle。

**SP-073** 数据目录不可写时游戏必须仍可启动；单个手动补丁组失败不得阻止其余补丁组、指标 hook、热键或语言事件安装；意图元数据初始化必须在 Harmony 安装后执行。

**SP-074** 版本库不得跟踪 `8.TEST` 下的测试日志与标准输出；发布 DLL 不得包含 `C:\Users\`、构建机桌面路径或 `obj\Debug` 路径。

## 12. 界面显示契约

**SP-061** 卡牌概率必须按当前进阶选择基础行；进阶7及以上必须使用普通61.51/37/1.49、精英55/40/5；负补偿必须同时降低罕见阈值；Boss战只显示「Boss奖励：稀有100%」；极速模式不得显示卡牌概率；「精英猎手」精英必须显示稀有100%、普通0%、罕见0%。

**SP-062** 药水概率必须在「白兽雕像」生效时显示100%；负值精英必须使用原始当前值加12.5个百分点；不得显示累计2至5场行；奖励生成后必须刷新为新值；极速模式不得显示药水概率。

**SP-063** 商店价格必须在遗物表增加「商店」稀有度行；不得显示半价卡；价格与金币必须取本地玩家；基础随机浮动必须按游戏取整，折扣、半价、删牌必须按游戏截断；删牌必须显示下一次价格；极速模式不得显示商店价格面板。

**SP-064** 未知房间面板必须在上一房间包含商店时将商店概率归零；不得为所有子节点均为商店、新档前两次未知、未来事件移除增加特殊显示。

**SP-065** 多段攻击图标必须按总伤害选档；被寄生的扭动虫位置2/4必须显示「生成→扭动」；单独小啃兽只显示「顶撞」；啃咬机必须按遭遇变体区分初始；英文界面必须显示 `<` 而不是 `&lt;`；外骨骼虫必须保留4号位；伤害数字不得改为实时修正预览。

**SP-066** 先古遗物选择率必须使用已选次数除以池内总已选次数；不得使用设计概率作为分母；必须修正A1、A2、A4、A6、A7、A8、A9、A10；不得为A3、A5、A11、A12增加修正。

## 13. 战斗归因目标（1.6.0）

注记（非规范性）：以下条款为 1.6.0 的已完成目标；验证范围见 `SPEC.md` 追溯表与 `3.DOCS/024-R-1.6.0-v0.113.1实机验证.md`。

**SP-075** 间接战斗效果必须归到实际来源；无法可靠判定来源时，必须显示未归因，不得把效果记到当前卡牌或无关来源。

**SP-076** 真实伤害守卫必须覆盖游戏实际调用的 `CreatureCmd.Damage` 根重载；同一目标只记一次；v0.111.1 的兼容重载不得重复记账。

**SP-077** 待定抽牌来源必须只在抽牌 hook 中设置，并在消费、hook 结束、回合边界或战斗边界清理；不得污染下一次抽牌。

**SP-078** 格挡池只允许在游戏实际清空格挡时清空；不得因无条件回合开始 hook 提前清空；壁垒、残影、坚固钳子等保留格挡的状态必须继续正确吸收伤害。

**SP-079** 战败路径必须 flush 当前战斗并记录玩家死亡；不得丢失最后一战；胜利、失败与放弃路径的收尾次数必须一致。

**SP-080** v0.113.1 的新职业内容至少覆盖 16 张能力牌和 15 个遗物；敌人、Dominion、内部状态能力和 5 个事件的战斗补丁不计入覆盖；v0.111.1 必须以运行时可选方式跳过新类型，不得因类型缺失阻断加载。

**SP-081** 战斗胜利后的遗物治疗（燃烧之血、黑暗之血、带骨肉）必须进入刚结束战斗记录，同时只能进入本局总计一次；战斗内首次治疗（包括修书小刀在 Doom 击杀后的治疗）必须进入当前战斗记录，不得因该场尚无其他贡献条目而写入本局总计。

## 14. 宠物吸收与损耗（1.7.0）

注记（非规范性）：本节定义 RQ-021 与 RQ-022 的对外数据与显示契约；实现见 `5.SDD/002-采集与统计.md` 与 `5.SDD/004-界面层.md`。

**SP-082** 贡献数据必须分别保存 `PetAbsorbed` 与 `PetWasted`；`PetAbsorbed` 表示宠物替玩家吸收时实际失去的 HP，`PetWasted` 表示主动击杀宠物浪费的剩余 HP；`EffectiveBlock` 不得写入两者。

**SP-083** 防御总量必须按 `EffectiveBlock + PetAbsorbed + 其他正向防御项 - SelfDamage - PetWasted` 计算；`PetWasted` 不得进入正向防御百分比的分母。

**SP-084** 奥斯提承伤必须把实际 HP 损失记入召唤来源的 `PetAbsorbed`；奥斯提父条必须保存为 `pet` 类型；不得把同一笔损失写入 `EffectiveBlock`。

**SP-085** 瓦皮承伤必须只统计本地玩家宠物、敌方攻击、实际失去的 HP；不得统计格挡、溢出伤害、队友宠物或非重定向伤害；瓦皮不得产生 `PetWasted`。

**SP-086** `PetWasted` 只允许在 `BONE_SHARDS` 或 `SACRIFICE` 主动击杀奥斯提时写入；玩家死亡清理、普通战斗死亡和其他卡牌不得写入；写入值必须等于击杀时的 `Osty.CurrentHp`，不得使用未持久化的 LIFO 堆栈，不得延迟到下一次受击。

**SP-087** 旧 JSON 读取时必须把 `osty` 类型归一化为 `pet`；旧奥斯提 `EffectiveBlock` 必须迁入 `PetAbsorbed`；旧负 `EffectiveBlock` 必须迁入 `PetWasted`；迁移必须幂等，旧对局总防御不得改变。

**SP-088** 奥斯提与瓦皮必须使用同一防御区、同一宠物色和 `[宠]` 前缀；奥斯提保留召唤卡子条，瓦皮只有父条；`PetWasted` 必须显示为独立红色「宠物损耗」负项，不得与自伤混显。
