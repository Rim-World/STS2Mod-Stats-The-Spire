## 1. 结论

1.7.2 已修复愚者旋律卡名称的占位符显示。v0.113.1 中文与英文探针各 7/7 PASS。地图悬停与设置持久化由用户确认正常，不在本次修改范围。用户尚未实机查看修复后的名称。

## 2. 现象与数据

用户截图中的异常名称与存档数据对应关系：

| 截图名称 | 实际 `SourceId` | 修复后期望 |
|---|---|---|
| `{MelodyWaText} 交` | `WAH_SYMPHONY` | `哇 交响乐` |
| `{MelodyWaText} 触` | `WAH_TOUCH` | `哇 触碰` |
| `{MelodyChoText} 影` | `CHO_READY` | `啾 就绪` |
| `{MelodyWaText} {N` | `WAH_KI` | `哇 叽` |
| `{MelodyChoText} {N` | `CHO_KI` | `啾 叽` |

截图中的伤害与防御数值与 `1795349355_XSY4EYPRTTJW` 的汇总一致，说明异常仅发生在名称解析，不在统计值。

## 3. 根因

- 游戏卡牌标题是 `LocString`。正常显示路径先调用 `GetFormattedText`，由 SmartFormat 解析占位符。
- 用户启用的 `FoolMelodyReplacer 0.3.2` 在 `LocTable.GetRawText` 后置补丁中，把旋律标题的原始前缀替换为 `{MelodyWaText}`、`{MelodyChoText}`、`{MelodyKiText}`，并注册自定义 SmartFormat source。
- 本 Mod 的 `NameLookup` 为了在模组语言与游戏语言不一致时选择正确文本，直接读取 `GetRawText`。它因此绕过了 SmartFormat，把原始占位符直接交给 Godot `Label`。
- 该问题只在安装会改写 raw 文本的第三方本地化模组时出现。原生游戏标题和普通卡牌名称不受影响。

## 4. 修改

修改文件：`9.SRC/src/Util/NameLookup.cs`。

- `TryLookup` 的当前语言路径改为 `FormatDisplayText`，内部调用 `LocString.GetFormattedText`。
- `ToDisplayText` 删除 `[img]`、`[color]`、`[lb]`、`[rb]` 等 BBCode；把 `{MelodyWaText}`、`{MelodyChoText}`、`{MelodyKiText}` 以及无 `Text` 后缀的旋律占位符替换为短名。
- `FormatDisplayText` 读取 raw 标题；当第三方模组使用图像-only 标题、格式化结果没有可见旋律文字时，使用 raw 文本重建名称。
- `MelodyShortName` 按 `L.Current` 返回中文 `哇`、`啾`、`叽` 或英文 `Wah`、`Cho`、`Ki`。不读取游戏当前语言的第三方设置表，避免英文界面混入中文名称。
- 英文回退路径仍优先使用 curated 名称或 `LocTable._fallback` 原文，但同样经过 `ToDisplayText`。
- 未安装第三方本地化模组时，`GetFormattedText` 返回普通标题；转换后名称与 1.7.1 一致。
