# 本局统计双窗口与信息密度调整

- 计划编号：028-S
- 建立时间：2026-11-23 00:42
- 状态：已实现（v0.113.1 布局探针 PASS；双版本 Release 构建 0 错误；1.8.0 已安装；用户实机视觉未做）
- 适用 Mod：1.8.0
- 游戏基准：v0.113.1（提交 `d09d48e5`），v0.111.1 用参考程序集构建

## 1. 目标

- 点击跑局历史左侧的「本局统计」后，同时显示两个窗口：左侧单局统计，右侧战斗贡献图表。
- 两个窗口一左一右排列，初始位置不重叠。
- 两个窗口按视口比例放大；总宽度约为视口的 65%，高度约为视口的 83%，不得占满屏幕。
- 删除 `RunHistoryStatsSection` 底部的「查看贡献图表」按钮及其入口逻辑。
- 左侧窗口删除重复标题，压缩分区间距和内边距；表格标签列不得吞掉全部横向空白。
- 关闭左侧窗口时同时关闭右侧回放窗口；关闭右侧窗口时左侧保留；Esc 和点击遮罩关闭全部。
- 右侧继续使用 `ContributionPanel` 的回放模式，保留 DPS、帮助、滚动和图表内容。
- 回放窗口不得保存拖动/缩放结果，避免污染实时贡献面板位置。

## 2. 非目标

- 不修改统计字段、JSON、存档或历史数据。
- 不修改贡献图表的归因、百分比、条宽或排序。
- 不修改实时战斗贡献面板的默认位置、尺寸与 F8 行为。
- 不修改游戏原生 `NRunHistory` 布局和按钮注入位置。

## 3. 设计

- `RunHistoryPatch` 负责两个根级窗口的几何布局：
  - 目标左宽 570，右宽 660，间距 16，目标高 900。
  - 根据视口宽高按比例缩放；窗口居中。
  - 右侧窗口由 `ContributionPanel.ShowRunReplayAt` 设置固定左上锚点、位置和尺寸，并置于遮罩之上。
- `RunHistoryStatsSection` 只生成单局统计内容，不再加载贡献汇总，不再创建回放入口。
- `ContributionPanel` 增加回放窗口布局方法；回放期间设置 `sts_replay_window` 元数据。
- `DraggablePanel` 与 `ResizablePanel` 忽略带 `sts_replay_window` 元数据的面板，避免保存回放布局。
