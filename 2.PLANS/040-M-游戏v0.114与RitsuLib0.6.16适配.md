# 游戏 v0.114.0 与 RitsuLib 0.6.16 适配

- 计划编号：040-M
- 时间：2026-11-27 03:07
- 状态：已完成（三版本构建、v0.114 加载与完整 AutoSlayer 胜利；v0.111.1 实机回归未做；RitsuLib Steam 审核阻塞发布）
- 目标 Mod 版本：1.10.0
- 需求：RQ-032
- 适用游戏：v0.111.1、v0.113.1、v0.114.0
- 依赖：`STS2.RitsuLib.Compat.0.111.0` 0.6.16（编译）；运行时 RitsuLib 0.6.16 对应游戏分支的变体

## 1. 问题

游戏已更新到 v0.114.0。RitsuLib 0.6.16 增加 0.114 兼容，同时保留 0.113、0.111 和 0.107.1。当前工程仍使用 RitsuLib 0.6.14，文档只声明 v0.111.1 与 v0.113.1。

0.114.0 的已知游戏 API 变化：

| API | v0.113.1 | v0.114.0 | 本项目现状 |
|---|---|---|---|
| `Creature.LoseHpInternal` | `DamageResult(decimal, ValueProp)` | `HpLossResult(decimal, bool dryRun = false)` | 未直接调用；通过 `CombatHistory.DamageReceived` 观察 |
| `Creature.DamageBlockInternal` | `decimal(decimal, ValueProp)` | 增加 `bool dryRun = false` | 未直接调用 |
| `CardModel.UpgradeInternal` | `void()` | `void(bool silent = false)` | 未直接调用；升级来源通过 `CardCmd.Upgrade` 观察 |
| `CardModel.DowngradeInternal` | `void()` | `void(int downgradeAmount = 1)` | 未直接调用 |
| `FreeCardPower` | 存在 | 删除 | 仅注释引用；无运行依赖 |
| `RapidShot` | 存在 | 改名/重做为 `TwinShot` | 无运行引用 |
| `HardToKillPower` | 限制伤害上限 | 改为限制 HP 损失 | 归因结果需实机核对 |

内容变化会影响统计口径，但多数由通用 hook 覆盖：

- 愚者「调音」从「回合结束给予免费牌」改为「获得 Ki 旋律时升级手牌」。`TunePower.AfterSideTurnEnd` 已不存在，旧目标必须改为 0.114 的 `TunePower.AfterCardPlayed` 或停止安装。
- 愚者「哇 叽」不再施加下回合能量；`KiRest` 仍通过 `EnergyNextTurnPower` 施加能量。现有按层分摊逻辑仍适用，但需核对。
- 新增「乐观」、重做「生长」「箭击」「花开」「射击」等愚者卡；通用卡牌、伤害、抽牌、能量 hook 应覆盖。
- 0.114 新增 `HpLossResult` 与 `DamageResults`；`CombatHistory.DamageReceived` 仍以 `DamageResult` 传递，核心观察点未变。

## 2. 适配项

1. 依赖升级
   - `PackageReference` 改为 `STS2.RitsuLib.Compat.0.111.0` 0.6.16，确保同一工程能分别对 v0.111.1、v0.113.1、v0.114.0 编译。
   - `manifest.json` 的 RitsuLib 依赖最低版本改为 `0.6.16`。
   - 玩家运行时安装完整 RitsuLib 0.6.16 文件夹；旧游戏使用对应 compat 变体，不复制 DLL 到本 Mod。
2. 代码适配
   - 检查所有 `[HarmonyPatch]` 与 `TryPatch` 目标在 0.114 的绑定结果。
   - 修复 `TunePower` 目标：0.114 使用 `AfterCardPlayed`；0.113 兼容路径保留或按运行时目标选择。
   - 核对 `HardToKillPower`、`LoseHpInternal`、宠物吸收、`DamageResult` 去重与击杀路径。
   - 不新增按版本生成的第二份 DLL；版本差异继续运行时探测。
3. 构建
   - 分别使用 v0.111.1、v0.113.1、v0.114.0 的 `sts2.dll` 构建，三份均 0 错误。
   - 以 0.114 构建生成一个 DLL，作为发布候选。
4. 运行验证
   - v0.114.0 + RitsuLib 0.6.16：无头加载，确认 `PatchInventory`、Fool 目标、主 Mod 初始化和依赖顺序。
   - 标准 AutoSlayer 完整局：覆盖普通战斗、精英、Boss、事件战斗、商店、战后治疗；对比 `.run`/贡献数据。
   - v0.113.1 回归：至少在切换回来时完成加载和补丁目标检查；优先完整局。
   - 未验证项必须写入报告：真实 UI、v0.111.1 运行、多人、视觉。
5. 文档与版本
   - 版本升到 1.10.0；同步 manifest、csproj、ModConfig、README、CHANGELOG、SPEC、SDD、PRD、输出包。
   - 记录 RitsuLib 0.6.16 尚未通过 Steam 审核的发布风险。

## 3. 风险

- RitsuLib 0.6.16 尚未在 Steam 过审时，发布依赖 `0.6.16` 的 Mod 会让创意工坊玩家无法满足依赖。必须等 RitsuLib 过审，或随 Mod 发布兼容的运行时变体。
- 0.114 是 Beta 分支；0.113.1 稳定分支仍需可用。一个 DLL 同时覆盖两个分支，`sts2.dll` 的编译基线取最低 API 版本，运行时由 RitsuLib 选择变体。
- `HardToKillPower` 改为 HP 损失上限后，实际伤害与格挡/减伤的统计口径可能变化，需以运行数据核对。
