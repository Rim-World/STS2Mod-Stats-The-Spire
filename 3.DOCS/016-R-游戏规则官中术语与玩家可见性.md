# 游戏规则核对：官中术语与玩家可见性

- 时间：2026-11-20 05:50
- 审阅修订：2026-11-20 20:19，按用户逐条批复修订；4 项口径待确认
- 对应报告：`3.DOCS/015-R-游戏公式与硬编码逻辑核对.md`
- 适用 Mod：1.5.1
- 游戏基准：v0.113.1（提交 `d09d48e5`）
- 目的：用游戏官方中文重写术语；说明每个错误在 Mod 里能不能看到、在哪里看到。

## 1. 怎么读

本文把玩家能看到的错误分成五种状态：

| 状态 | 含义 |
|---|---|
| 能（常驻） | 默认设置下打开对应界面就能看到 |
| 能（悬停） | 鼠标移到指定图标、节点或敌人身上才能看到 |
| 能（条件） | 只有进阶、模式、遗物、多人游戏等条件成立时才出现 |
| 不能（当前版本） | 代码里有缺口，但当前版本不会显示给玩家 |
| 未确认 | 源码看不出确定结果，或没有运行验证 |

官中来源是游戏 v0.113.1 的 `localization/zhs` 表。本文去掉 `[gold]`、`[blue]` 这类富文本标记，只保留显示文字。

游戏没有给代码内部变量起官中名字。本文正文用「当前值」「补偿值」「有效权重」这类描述，不是官方术语；代码名放在最后的「内部变量对照」。这样不会把自造词伪装成官中。

模组界面里的「幕」不是游戏官中。游戏官中用「阶段」，例如「阶段1」。下文引用模组原文时写「第N幕」，解释规则时写「阶段N」。

## 2. 卡牌奖励

位置：对局顶部，地图按钮左侧的卡牌图标；鼠标悬停后出现「卡牌掉落(下一场)」。默认开启。

| 编号 | 玩家看到什么 | 正确的游戏规则 | 可见性 |
|---|---|---|---|
| C1 | 进阶7及以上，普通战斗仍显示稀有3%、罕见37%；精英战斗仍显示稀有10%、罕见40% | 进阶7「稀缺」后，普通战斗稀有1.49%、罕见37%、普通61.51%；精英战斗稀有5%、罕见40%、普通55% | 能（进阶7+） |
| C2 | 初始状态或负补偿时，普通概率偏高、罕见概率偏低 | 负的稀有阈值要同时从罕见概率扣除，剩余才给普通 | 能（所有进阶，初始 -5%） |
| C3 | 副标题写「各稀有度至少出现一张」，表里是单张概率 | 一次卡牌奖励通常有3张；不能用单张概率直接代表「至少一张」 | 能（悬停） |
| C4 | Boss战、极速模式、自定义特效「精英猎手」时，仍显示普通/精英概率表 | Boss奖励固定稀有；极速模式不显示概率；「精英猎手」下精英奖励100%稀有 | 能（条件；Boss处置待确认） |
| C5 | 刚开局或刚打开开关，悬停表按零补偿计算 | 正常路径先读取当前补偿再显示；不应按零补偿计算 | 未确认（初始化瞬态） |

### 2.1 基础概率

| 进阶 | 普通战斗（普通/罕见/稀有） | 精英战斗（普通/罕见/稀有） |
|---|---|---|
| 0-6 | 60% / 37% / 3% | 50% / 40% / 10% |
| 7+「稀缺」 | 61.51% / 37% / 1.49% | 55% / 40% / 5% |

模组固定使用第一行。玩家当前是进阶10，所以普通战斗和精英战斗的基础值都错。

### 2.2 负补偿的算法

游戏先算稀有阈值，再算罕见阈值：

```text
稀有阈值 = 基础稀有 + 当前补偿
罕见阈值 = 基础罕见 + 稀有阈值
```

当前补偿为 -5% 时：

| 状态 | 游戏（普通/罕见/稀有） | 模组（普通/罕见/稀有） |
|---|---|---|
| 进阶0，初始 -5% | 65% / 35% / 0% | 63% / 37% / 0% |
| 进阶7+，初始 -5% | 66.51% / 33.49% / 0% | 63% / 37% / 0% |
| 进阶7+，补偿 0 | 61.51% / 37% / 1.49% | 60% / 37% / 3% |
| 进阶7+ 精英，补偿 0 | 55% / 40% / 5% | 50% / 40% / 10% |

所以 C1 不是唯一问题。即使进阶0，初始状态也错。

### 2.3 「至少一张」不一致

普通战斗初始单张稀有是3%。一次奖励3张时，至少一张稀有约为：

```text
1 - (1 - 0.03)^3 = 8.7%
```

精英战斗单张稀有是10%，至少一张约为27.1%。面板显示3%和10%，副标题却承诺「至少一张」。这两个数不是同一个量。

### 2.4 Boss、极速和「精英猎手」

- Boss奖励使用固定的稀有卡池，不走普通/精英表。面板没有Boss列。
- 极速模式的普通战斗固定给普通卡，精英固定给罕见卡；Boss奖励按报告记录为固定稀有。
- 自定义模式的特效「精英猎手」会把精英奖励改成只出稀有牌。面板仍显示稀有10%或5%。

这三种情况都能在顶部卡牌图标悬停时看到，但需要对应条件。

用户批复：

- C4 不新增 Boss 列；极速模式不显示卡牌概率；「精英猎手」把精英行改成稀有100%、普通0%、罕见0%。
- Boss战是隐藏整表还是显示一行「Boss奖励：稀有100%」，见第15节待确认项。
- C5 不是新档第一把或首次启用 Mod 的专属问题。正常路径在显示前刷新当前补偿；只有刷新失败或界面重建的瞬间可能看到零偏移。未确认可复现。

## 3. 药水奖励

位置：对局顶部，地图按钮左侧的药水图标和百分比；鼠标悬停后出现「药水掉落（下一场）」。默认开启。

| 编号 | 玩家看到什么 | 正确的游戏规则 | 可见性 |
|---|---|---|---|
| P1 | 持有「白兽雕像」时仍显示40%到90%的普通概率 | 「白兽雕像」让战斗结束后的药水奖励必定出现，实际是100%；它不改变当前概率值 | 能（持有白兽雕像） |
| P2 | 当前概率为 -10% 时，精英战显示12.5%，实际是2.5% | 游戏不会把当前值夹到0；精英加成是在原始负值上加12.5个百分点 | 能（当前值为负） |
| P3 | 刚开局或刚打开开关，顶部显示「—」 | 正常路径先读取当前药水概率再显示；不应长期显示占位符 | 未确认（初始化瞬态） |
| P4 | 悬停表的「2/3/4/5场内」没有说明假设 | 这些行按每场都是普通战斗、每场都未掉落计算；精英战和强制掉落会改变结果 | 用户批复：删除 |
| P5 | 战斗奖励界面悬停时，数字还是「刚用过的那次」 | 奖励生成后当前值已经下降，下一场才按新值计算 | 用户批复：显示新值 |
| P6 | 代码支持「任意一场精英」参数，但当前都传「否」 | 当前调用固定按普通战斗算，所以暂时不会显示错误 | 只影响P4；P4删除后无可见入口 |

### 3.1 已经正确的部分

- 普通战斗基准40%、每次掉落后当前值下降10个百分点，这两项正确。
- 精英加成12.5个百分点正确。它是精英奖励25%的一半。
- 「白兽雕像」之外，当前没有发现强制药水奖励的遗物。

### 3.2 负值例子

当前值为 -10% 时：

- 普通战斗实际概率为0，模组显示0，正确。
- 精英战斗实际概率是 `-10% + 12.5% = 2.5%`，模组先把当前值夹到0，再显示12.5%，高估10个百分点。
- 后续累计概率也会从0起步，而不是从 -10% 起步，整张累计表会前移。

### 3.3 白兽雕像

「白兽雕像」的官中描述是「战斗结束后必定掉落药水」。游戏在正常滚概率之前检查强制奖励，命中后不修改当前值。面板只读当前值，所以看不到这个100%。

### 3.4 初始化状态

`PotionOddsIndicator` 的标签初始值是「—」。`OnRunStarted` 创建指示器后，先调用 `RefreshValuesFromPlayer`，再调用 `ShowAll`。药水当前值读取失败时回退40%。

因此 P3 不是“新档第一把”或“首次启用 Mod”的专属问题。正常路径下不会长期显示「—」。只有刷新失败、或界面重建后尚未刷新的一帧可能看到占位符。未确认可复现。

P6 只影响累计行。顶部「精英战」一行使用单独的 `current + 12.5` 计算。P4 删除后，P6 没有可见入口。

## 4. 商店价格

位置：地图界面，鼠标移到未进入的商店节点；出现「商店价格」。默认开启。

| 编号 | 玩家看到什么 | 正确的游戏规则 | 可见性 |
|---|---|---|---|
| S1 | 遗物表只有普通/罕见/稀有，没有商店遗物 | 标准商店固定有一个「商店」稀有度遗物，价格200金币，上下浮动15% | 用户批复：新增商店行；与4.2冲突待确认 |
| S2 | 卡牌表只显示50/75/150的普通区间，没有半价提示 | 标准商店固定有一张角色牌半价 | 用户批复：不显示；与S1冲突待确认 |
| S3 | 折后价可能比游戏高1金币 | 游戏在折扣、半价、删牌路径上截断；基础随机浮动仍取整 | 能（折后价为 .5 时） |
| S4 | 面板保持打开时使用删牌服务，价格不自动刷新 | 应显示下一次删牌价格；当前悬停重算已经按已用次数取下一次价格 | 能（条件：面板保持打开） |
| S5 | 多人游戏里，价格和金币可能按第一名玩家算 | 应取本地玩家；多人游戏里第一名不一定是自己 | 用户批复：修 |
| S6 | 极速模式的商店仍显示标准价格和删牌费 | 极速商店条目免费；显示方式待确认 | 用户批复：待确认 |
| S7 | 未来新增价格修改遗物时，面板可能漏算 | 游戏会遍历所有商人价格修正；模组只认「会员卡」和「送货员」 | 不修（未来问题） |

### 4.1 已经正确的部分

- 普通/罕见/稀有遗物：175 / 225 / 275金币，上下浮动15%。
- 普通/罕见/稀有卡牌：50 / 75 / 150金币，上下浮动5%。
- 普通/罕见/稀有药水：50 / 75 / 100金币，上下浮动5%。
- 「会员卡」五折和「送货员」八折，当前版本叠加结果正确。
- 无色牌加价15%。

普通商品价格不使用进阶加成。只有删牌费读取进阶15「通货膨胀」：基础费 75/25 变成 100/50。当前面板通过 `BaseCost`、`PriceIncrease` 读取实时值。

无色牌当前只有提示，没有具体数值。按游戏公式，未打折基础值约为 58 / 86 / 173；随机浮动范围约为 55-61、82-90、164-182。折后按游戏顺序计算并截断。

### 4.2 两个固定例外

标准商店的遗物位置固定为：

1. 两个随机普通/罕见/稀有遗物。
2. 一个「商店」稀有度遗物，价格200金币。

卡牌位置还会把一张角色牌设为半价。面板只按三个稀有度列显示区间，所以这两个固定结构都看不到。

用户批复在 S1 要求新增「商店」行，在 S2 又要求不显示半价结构。两者是否同时执行，见第15节待确认项。

### 4.3 舍入

基础删牌费75金币，「会员卡」五折：

```text
游戏：75 × 0.5 = 37.5，转整数得37
模组：Math.Round(37.5) = 38
```

所以面板可能比实际价格高1金币。

不能把所有价格统一改向下取整。游戏在基础随机浮动上使用取整，在折扣、半价和删牌路径上使用转整数截断。按具体路径对齐。

## 5. 未知房间

位置：地图界面，鼠标移到未进入的未知（?）节点；出现「下一个 [?] 房间」。默认开启。

| 编号 | 玩家看到什么 | 正确的游戏规则 | 可见性 |
|---|---|---|---|
| U1 | 上一个房间是商店时，未知房间仍显示商店概率 | 上一个房间有商店时，下一个未知房间不能出商店；概率要分给事件 | 能（条件） |
| U2 | 当前节点的所有子节点都是商店时，未知房间仍显示商店概率 | 所有子节点都是商店时，未知房间不能出商店；但「飞翼靴」允许自由移动，不能保证下一步 | 用户批复：不修 |
| U3 | 新档的前两个未知房间仍显示普通概率 | 新档前两个未知房间固定事件，第三个固定怪物 | 能（新档） |
| U4 | 将来有移除事件的效果时，事件概率会显示0，残余概率不显示 | 事件被移除时，剩余概率应落到第一个可用房间类型 | 不能（当前版本） |

### 5.1 已经正确的部分

- 「佛珠手链」移除普通怪物；v0.113.1 还移除精英。
- 「黄金罗盘」强制事件。
- 「灯火钥匙」是任务牌，不是遗物；它在阶段3强制事件。
- 这些来源通过游戏钩子生效，面板会跟着隐藏对应行，并把概率重新分给事件。

模组的遗物提示文字写「金罗盘」，游戏官中是「黄金罗盘」。这是文字不一致，不影响概率计算。

### 5.2 新档固定结果

游戏在「已完成对局数为0」时，按此前访问过的未知房间数量判断：

- 访问数小于2：强制事件。
- 访问数等于2：强制怪物。

所以新档前两个未知房间都是100%事件，第三个是100%怪物。面板没有读取这个状态，仍显示基础概率。用户批复：不专门适配新档第一把。

U2 在源码上可以检测：`RunManager.BuildRoomTypeBlacklist` 会用 `nextMapPoints.All(Shop)` 判断。但「飞翼靴」的 `ShouldAllowFreeTravel` 允许玩家跳到下一排任意节点，因此“所有子节点都是商店”不能推出“下一步一定进商店”。按用户批复不修。

## 6. 意图状态机

位置：战斗中，鼠标移到存活敌人身上；出现「意图状态机」浮窗。默认开启。

| 编号 | 玩家看到什么 | 正确的游戏规则 | 可见性 |
|---|---|---|---|
| I1 | 随机分支的百分比是设计权重，不是当前回合真实概率 | 游戏会应用「整场一次」「不能连续使用」「连续次数上限」「冷却」等过滤 | 能（随机分支怪物） |
| I2 | 「不能连续使用」显示成「≤1」 | 它的意思是不能连着用，不是整场只能用一次；整场一次才显示「×1」 | 能（悬停） |
| I3 | 多段攻击的图标档位偏低 | 游戏按总伤害选图标；5×5按25选档，不按单次5选档 | 用户批复：修 |
| I4 | 敌人有力量、玩家有虚弱/易伤时，伤害数字与游戏意图不一致 | 游戏预览会应用伤害修正、力量、虚弱、易伤，再取整并下限0 | 不作为错误：只显示设计意图 |
| I5 | 「扭动虫」被寄生的位置2/4也显示「生成→污秽啃咬」 | 位置2/4应显示「生成→扭动」；位置1/3才是「污秽啃咬」 | 用户批复：修 |
| I6 | 单独出现的「小啃兽」把「顶撞」标成「背面」 | 单独出现时只有一个分支「顶撞」，没有背面/正面 | 用户批复：修 |
| I7 | 「异螨」「花园幽灵鳗」的初始条件框不显示，面板从第一个招式开始 | 两者都有初始条件分支，应按1/2号位或1-4号位展开 | 用户批复：不修 |
| I8 | 「骇鳗」多出一个「晕眩 HP<50%」入口 | 这个晕眩招式没有入边；实际是「尖叫」触发临时「晕眩」，再进「恐吓」 | 用户批复：不修 |
| I9 | 「咬人卷轴」的初始标签写成「1/2/3号位初始」 | 初始由随机/轮转决定；第四只固定「更多牙齿」，不是3号位 | 用户批复：不修 |
| I10 | 「啃咬机」把「尖锐鸣叫」标成「2号位初始」 | 初始由「先尖叫」遭遇变体决定；在「地道组合」中它是1号位 | 用户批复：修 |
| I11 | 「实验体」的「重生」分支被隐藏，复活条件框悬空 | 「重生」由运行期直接跳转进入，没有静态入边；应保留 | 用户批复：不修 |
| I12 | 「女王」把死亡分支显示成「激怒」 | 游戏原分支是「将头砍下」；只有下一招是「为我尽力燃烧吧」时才改成「激怒」 | 用户批复：不修 |
| I13 | 正常「外骨骼虫」有4个槽位 | 正常遭遇4槽；弱遭遇3槽；4号位分支合法 | 用户批复：保留 |
| I14 | 英文界面显示 `Revived &lt;2`、`Count &lt;3` | 普通文本不解析HTML实体，应显示 `<` | 用户批复：修 |
| I15 | 进阶8且实时数据不可用时，地精佣兵回退缓存显示标准档伤害 | 地精佣兵三种攻击在进阶8和9都是8/7/9；缓存只按进阶9分档，进阶8落入标准档 | 未确认（实时路径通常正常） |

### 6.1 百分比的实际含义

例：墨宝刚用过「刺击」后，游戏会把「刺击」的权重过滤为0，实际「旋风」100%。面板仍显示50/50。

所以百分比应该写成「基础权重」，或者按当前状态重新计算有效权重。当前界面两者都没有标明。

### 6.2 多段攻击

游戏用总伤害选攻击图标档位。5×5的多段攻击总伤害是25，应该选第3档；模组传单次5，选第2档。图标看起来会比实际弱。

### 6.3 伤害数字

模组显示的是伤害计算原始值，没有走游戏的伤害修正。敌人有「力量」、玩家有「虚弱」或「易伤」时，面板数字会偏离游戏意图图标上的数字。

### 6.4 初始条件框缺失

「异螨」和「花园幽灵鳗」的初始条件状态没有进入状态集合。面板找不到起始状态，就退回第一个招式，把「浓毒」或「啃咬」当成初始。玩家看不到1/2号位、1-4号位的初始说明。

「骇鳗」的晕眩招式同样不在可达路径里，但模组强行把它显示出来，形成一个游戏不会经过的假入口。

「实验体」的重生由运行期直接跳转进入，状态机没有静态边。面板把「重生」当不可达并隐藏，后面的复活条件框就失去来源。

「女王」的死亡分支被模组无条件改成「激怒」。如果玩家在第一次「为我尽力燃烧吧」之前击杀火炬头聚合体，游戏实际会走「将头砍下」，面板却显示「激怒」。

### 6.5 I15 的根因

地精佣兵没有昏晕招式。它的三种攻击都读取 `ToughEnemies`（进阶8）：进阶0-7为 7/6/8，进阶8及以上为 8/7/9。因此对这个怪物，进阶8和9的实际伤害相同。

问题在缓存分档：

- `MonsterIntentMetadata.IsCurrentRunDeadly()` 只检查进阶9 `DeadlyEnemies`。
- 进阶8时，缓存键是 `deadly=false`，使用标准档。
- 标准档烘焙时关闭了 `ToughEnemies`，所以回退数据是 7/6/8。
- 进阶9时，缓存键是 `deadly=true`，同时强制进阶8和9，得到正确的 8/7/9。

`IntentStateMachinePanel` 在悬停时传入实时怪物，实时路径通常正确。只有实时状态机构建失败或没有实时怪物时，才会使用错误缓存。I15 不是昏晕意图，也不是“进阶8和9伤害不同”。

### 7.1 达弗的结构与概率

游戏的实际流程：

1. 从11组候选遗物中，每组按条件抽1个。
2. 打乱这组结果。
3. 50%取前2个并追加「尘封魔典」，50%取前3个。

所以共有11个候选组遗物加1个「尘封魔典」，不是11个遗物含「尘封魔典」。

假设11组全部可用：

| 对象 | 玩家遇到概率 | 占全部选项槽位 |
|---|---:|---:|
| 尘封魔典 | 50% | `50% × 1/3 = 1/6` |
| 其余每个遗物 | `50% × 2/11 + 50% × 3/11 = 5/22` | `(5/6) / 11 = 5/66` |

用户批复里的 `50% × 3/11 + 50% × 2/10 = 13/55` 把50%分支的抽取池写成10个。实际是从11组里抽2个，再追加尘封。`5/6 / 10 = 1/12` 也把其余遗物数量写成10个。实际是11个，所以每项是 `5/66`。

如果某些候选组被当前阶段过滤，把11换成实际可用的 `N`，再按同一结构计算。

当前面板的“选择率”是已选次数除以池内总已选次数，不读取上述设计概率。用户要求显示“玩家选择的占比”时，这些概率不参与计算；A3、A5不作为公式错误处理。

### 7.2 达弗的阶段限制

- 「灵体外质」「添水」：阶段2。模组标「只在第2幕出现」，正确。
- 「贤者之石」「天鹅绒颈圈」：阶段2或阶段3。模组标「只在第3幕出现」，错误。

模组界面写「幕」，游戏官中写「阶段」。用户批复：界面保留「幕」，只修阶段映射。本文引用模组时保留「幕」。

### 7.3 涅奥的错位

静态表把「卷轴箱」放进诅咒池，把「华美发束」放进正面池。动态补充会把「华美发束」移到诅咒池，但只添加、不删除，所以「卷轴箱」仍留在诅咒池。

动态补充只执行一次。任一步骤失败后，进程内永久使用手写表；读取不到涅奥时也没有告警。玩家看到的是缺项或错池。

### 7.5 A12 的核实

`BetaRemovedBosses` 含 `DOORMAKER_BOSS`。代码只在 `CurrentBranch == Beta` 时过滤。正式分支 `isBeta=false`，历史 `BossStats` 会把 `DOORMAKER_BOSS` 加回下拉。

本地历史存档已有20多个 `.run` 文件包含 `DOORMAKER_BOSS`。因此过滤不是空操作：Beta 隐藏，正式分支显示历史记录。用户批复不修，保留该行为。
