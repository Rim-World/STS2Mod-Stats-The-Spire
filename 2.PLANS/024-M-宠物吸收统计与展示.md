## 1. 目标

新增独立字段 `PetAbsorbed`，统计宠物用生命值替玩家吸收的伤害，并在现有防御区同时展示奥斯提与瓦皮。

完成后的行为：

1. 奥斯提的吸收量从 `EffectiveBlock` 移入 `PetAbsorbed`。
2. 瓦皮实际失去的生命值记入 `PetAbsorbed`。
3. 两种宠物使用同一来源类型、同一颜色、同一防御区、同一百分比口径。
4. 旧对局数据中的奥斯提吸收迁移到 `PetAbsorbed`，不重复计入。
5. 不改变真实格挡、自伤和其他防御来源的既有数值。

## 2. 背景

当前代码把奥斯提 HP 吸收写入 `EffectiveBlock`。该字段的定义是“被格挡吸收的伤害”。瓦皮承受敌方攻击后，伤害被直接排除，没有防御记录。

用户已批准新增独立字段 `PetAbsorbed`。理由是数据层需要区分：

- 格挡消耗：玩家格挡点数被消耗。
- 宠物 HP 吸收：宠物实际失去生命值。

两者可以在同一个“防御”界面展示，但不得在存储层失去区别。

## 3. 范围

### 3.1 数据模型

- 在 `ContributionAccum` 增加 `PetAbsorbed`。
- `TotalDefense` 增加 `PetAbsorbed`。
- `MergeFrom` 合并 `PetAbsorbed`。
- 所有构造、复制、克隆路径包含 `PetAbsorbed`。

### 3.2 奥斯提

- `CombatHistoryPatch` 检测奥斯提承伤后传入宠物承伤标记。
- `CombatTracker.OnOstyAbsorbedDamage` 改为写 `PetAbsorbed`。
- 继续使用现有 LIFO 召唤来源栈；召唤卡作为 `OSTY` 子条。
- HP 栈不足时，余量记到 `OSTY` 父条。
- 复核 `_pendingOstyDeathDefense` 的负防御语义；该决定必须有测试固定。当前实现见 `9.SRC/src/Collection/CombatTracker.cs:695` 与 `:1608`。处理选项见 §3.8。

### 3.3 瓦皮

- 用运行时类型名或安全反射识别 `receiver.Monster` 为瓦皮，禁止在 v0.111.1 路径直接引用 v0.113 才存在的 `Wuppy` 类型。
- 仅当 `receiver.PetOwner` 是本地玩家时统计。
- 取宠物承伤 `DamageResult.TotalDamage`，即实际失去的 HP；不得取 `IntendedHpLoss`，不得计 `OverkillDamage`。
- 直接记到 `WUPPY` 父条；不按当前卡牌或能力上下文归因。
- 瓦皮死亡、当前 HP 为 0 或未触发忠诚重定向时，不产生记录。
- 不统计瓦皮被治疗、休息恢复或遗物显示的生命值。

### 3.4 通用宠物过滤

- 奥斯提与瓦皮都使用 `receiver.PetOwner` 和 `IsLocalPlayer` 判断本地归属。
- 队友宠物承伤不得进入本地统计。
- 保留敌方对敌人、敌方对非本地宠物的排除路径。

### 3.5 持久化与汇总

- `ContributionPersistence.SourceDto` 增加 `PetAbsorbed`。
- `ToDto`、`FromDto`、`SaveCombat`、`SaveSummary`、`LoadSummary`、`BuildMerged` 全部包含该字段。
- `RunContributionAggregator` 的内存累计、每场快照、磁盘合并和克隆全部包含该字段。
- 旧 JSON 缺少 `PetAbsorbed` 时按 0 读取。
- 旧奥斯提数据（`SourceType == "osty"` 或 `OriginSourceId == "OSTY"`）在读取时把 `EffectiveBlock` 迁移到 `PetAbsorbed`，并把旧字段清零，避免双计。
- 迁移必须幂等；重复加载不得重复迁移。

### 3.6 界面

- `OSTY` 与 `WUPPY` 使用统一来源类型 `pet`。
- 两行都放入现有“防御”区，前缀使用 `[宠]`。
- 奥斯提保留召唤卡子条；瓦皮只有父条。
- `PetAbsorbed` 使用宠物色；防御总量和百分比包含该字段。
- 旧数据中的 `osty` 类型必须兼容读取；读取时归一化为 `pet`，保存时写 `pet`。
- `SourceId` 保留 `OSTY`；显示名仍从 `OSTY` 查询为“奥斯提”。旧类型只影响分类、颜色和前缀，不改变来源名称。
- 奥斯提显示名改为本地化“奥斯提”；瓦皮显示名改为本地化“瓦皮”。
- 帮助面板增加“宠物吸收”定义：宠物实际失去的生命值，不含溢出伤害。
- 更新 `contrib.help_block`，不得继续把宠物吸收描述成格挡。

### 3.7 兼容与发布

- v0.113.1 与 v0.111.1 均可加载。
- v0.111.1 没有瓦皮时，不出现类型加载异常；奥斯提仍可统计。
- 版本号统一到 1.7.0。
- 生成 1.7.0 输出包、更新 CHANGELOG、README 与安装验证。

### 3.8 奥斯提死亡剩余 HP 的处理选项

当前实现：

- 奥斯提死亡时，读取剩余 HP。
- 下一位敌人攻击玩家时，从击杀卡（例如碎骨）的 `EffectiveBlock` 扣除这笔剩余 HP。
- 代码位置：`9.SRC/src/Collection/CombatTracker.cs:695`、`:1608`。

这笔“负防御”只改统计，不改游戏 HP，也不改格挡。

**示例：碎骨获得 10 点格挡，奥斯提剩 1 点 HP**

当前代码不会得到 11。实际顺序如下：

| 时点 | 游戏内 | 统计内 |
|---|---|---|
| 碎骨打出 | 玩家获得 10 点格挡 | 0（格挡尚未消耗） |
| 碎骨杀死奥斯提 | 奥斯提死亡，剩余 1 HP 消失 | 记下待扣的 1 |
| 下一次敌人攻击玩家 | 10 点格挡被消耗 | 先扣 1，再记 10 点有效格挡 |
| 结算后 | 实际格挡 10 | 9 |

这里有两个口径：

- 实际有效格挡：10 点。它回答“这张卡实际挡住了多少伤害”。
- 净防御：10 − 1 = 9 点。它把“浪费 1 点奥斯提 HP”的机会成本也算进去。

当前代码把净防御写进 `EffectiveBlock`，所以显示为 9。它没有把剩余 HP 加进吸收，因此不会得到 11。相对“实际有效格挡”口径，当前代码少记 1 点，不是多记 1 点。

删除这笔负防御后，结果是 10，不是 11。删除动作只停止扣减，不会把剩余 HP 加进吸收。

旧 JSON 中已经存在的击杀卡负值保留，不回写历史数据。新版本只停止生成新的负值。

可选处理：

| 选项 | 动作 | 后果 | 评价 |
|---|---|---|---|
| A | 删除这笔负防御 | 剩余 HP 本来就没计入吸收，不会产生双计；牺牲卡的防御不再变负 | 推荐 |
| B | 改记到 `PetAbsorbed`，允许负数 | 保留“浪费宠物 HP”的惩罚；但 `PetAbsorbed` 同时表示吸收和损失，语义混合 | 不推荐 |
| C | 继续留在 `EffectiveBlock` | 改动最小；但 `EffectiveBlock` 不再只表示真实格挡，违反 RQ-021 | 不推荐 |
| D | 新增 `PetWasted` 字段 | 语义最清楚；但增加字段、界面和测试范围 | 本轮不做 |

本计划默认采用 A；用户确认后写入 SPEC 和测试。

## 4. 非目标

- 不改变游戏平衡、存档或游戏二进制。
- 不统计宠物格挡；瓦皮走 `LoseHpInternal`，本轮只统计 HP 吸收。
- 不统计溢出伤害。
- 不为宠物治疗、休息恢复或遗物显示增加贡献统计。
- 不新增奥斯提/瓦皮以外的宠物类型；通用过滤器只保留扩展点。
- 不重写现有 107 个战斗补丁。
- 不处理 RQ-016 的 GitHub 旧对象清除。
- 不处理人工 F8、面板视觉与完整真人流程验收。

## 6. 验收

- `PetAbsorbed` 出现在战斗 JSON、summary JSON 和 live JSON。
- 旧 JSON 读取后，奥斯提数值进入 `PetAbsorbed`，`EffectiveBlock` 不保留同一笔数值。
- 奥斯提吸入之和等于其实际 HP 损失；LIFO 来源与召唤卡对应。
- 瓦皮吸入之和等于其实际 HP 损失；玩家 HP 不因该次攻击减少。
- 溢出伤害不计入；瓦皮死亡后不新增吸收。
- 队友宠物承伤不计入本地。
- 防御总量 = 真实格挡 + 宠物吸收 + 其他防御项 - 自伤。
- 旧对局总防御与迁移前一致，不出现双计。
- v0.113.1 与 v0.111.1 Release 构建 0 错误。
- v0.111.1 加载无 `Wuppy` 类型异常。
- 面板显示 `[宠] 奥斯提` 和 `[宠] 瓦皮`，同一防御区和百分比。

## 8. 风险与回滚

| 风险 | 处理 |
|---|---|
| v0.111.1 直接引用 `Wuppy` 类型 | 使用运行时类型名或缓存反射；构建后做 v111 加载探针 |
| 旧数据迁移双计 | 迁移前备份样本；迁移幂等；总防御回归对比 |
| `EffectiveBlock` 与 `PetAbsorbed` 加总错误 | 用固定样本手算；覆盖 JSON、live、summary 三层 |
| 奥斯提死亡负防御语义改变 | 单独测试；不在无证据时改口径 |
| 瓦皮死亡后仍被统计 | 检查 `PetOwner`、`IsAlive`、当前 HP 和重定向结果 |
| 多人远程宠物污染 | 统一本地 `PetOwner` 过滤 |
| 面板出现两套重复宠物区 | 只保留防御区一套父行/子行 |

回滚：

- 保留 1.6.1 源码和 DLL。
- 数据迁移只在新字段上操作；旧 JSON 原文件不覆盖。
- 若 UI 异常，可先关闭宠物行显示，不回滚已写入的 `PetAbsorbed` 数据。
