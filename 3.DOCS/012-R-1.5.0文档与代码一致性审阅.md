## 2. 代码与规范不一致

### 2.1 高：启动清理会删除 legacy 文件

`ContributionPersistence.PruneOldFiles` 在 `9.SRC/src/Util/ContributionPersistence.cs:442-448` 枚举 `contributions/*.json`，删除 90 天前的所有扁平文件。该函数由 `9.SRC/src/CommunityStatsMod.cs:39` 在启动时调用。

这违反 `6.SPEC/001-总体规范.md:143` 的 SP-057：旧版 `{seed}_*.json` 在归属不确定时不得自动删除。

影响：升级后首次启动可能删除 `{seed}_summary.json`、`{seed}_live.json`、`{seed}_shop_purchases.json`，导致旧历史回放缺失。

建议：只清理新目录 `{StartTime}_{seed}/`；legacy 扁平文件不自动删除。

### 2.2 高：StartTime 缺失时会写入 legacy 路径

`RunIdentity.HasStartTime == false` 时，`RunDataCollector.ResumeRun` 与各持久化类仍走 legacy 路径：

- `9.SRC/src/Collection/RunDataCollector.cs:95-99`
- `9.SRC/src/Util/ContributionPersistence.cs:145-162`、`:342-370`
- `9.SRC/src/Util/ShopOfferingPersistence.cs:20-30`
- `9.SRC/src/Util/ShopPurchasePersistence.cs:22-32`

这会覆盖同 seed 的旧 live、summary、shop 文件，并在收尾时删除 legacy live/offers。SDD 与源码注释声称 legacy 只读，实际行为不一致。

建议：无有效 StartTime 时禁止写入 legacy 路径，记录警告并保持内存态；或明确设计一个降级目录。

### 2.3 中：legacy 续局的商店购买没有写入新目录

`RunDataCollector.ResumeRun` 从 legacy 文件加载 `_shopPurchases`（`9.SRC/src/Collection/RunDataCollector.cs:98-99`），但收尾 `OnMetricsUpload` 不保存该列表（`:166-177`）。只有发生新购买时才调用 `ShopPurchasePersistence.Save`。

影响：1.4.4 存档续局后如果没有再购买，历史分析按新目录找不到 `shop_purchases.json`，`CardsBought` 会少计。

建议：收尾时把内存中的合并购买列表复制到当前 RunKey 目录；不要移动或删除 legacy 文件。

### 2.4 中：设置损坏时没有警告

`9.SRC/src/Config/ModConfig.cs:138` 与 `9.SRC/src/Config/FilterSettings.cs:148` 捕获异常后静默返回默认值。

这违反 `SP-016`：设置文件损坏时必须记录警告并使用默认值。当前只使用默认值，没有警告。

建议：在两个 catch 分支调用 `Safe.Warn`，保留默认值回退。

### 2.5 低：manifest 允许未测试的 0.111.0

`9.SRC/manifest.json:10` 与 `10.OUTPUT/1.5.0/manifest.json:10` 的 `min_game_version` 为 `0.111.0`；文档基线为 `v0.111.1` 与 `v0.113.1`。

影响：游戏 v0.111.0 会加载 Mod，但该版本未验证。

建议：把 `min_game_version` 改为 `0.111.1`，或明确声明 0.111.0 也是支持范围。

### 2.6 低：空对局不写 summary

`ContributionPersistence.SaveRunSummary` 在数据为空时提前返回（`9.SRC/src/Util/ContributionPersistence.cs:147`）。SDD 002 原先把“写入 summary.json”写成无条件行为。

已把 SDD 002 改为“有贡献数据时写入”。如果要求空对局也可回放，需要改为写入空摘要。

### 2.7 低：缓存 TTL 文档与实现不一致

`ModConfig.MemoryCacheTtlSeconds` 与 `DiskCacheTtlHours` 没有被缓存清理逻辑读取；`RunHistoryAnalyzer` 主要在失效时重建，`CareerStatsCache` 没有 TTL 检查。

已在 SDD 001 中标注“TTL 字段当前没有驱动清理”。如果要保留 TTL 规范，需要补实现。
