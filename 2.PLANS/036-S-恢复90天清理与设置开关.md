# 恢复 90 天清理并增加设置开关

- 计划编号：036-S
- 建立时间：2026-11-25 04:21
- 状态：已完成（1.9.3 已安装；自动清理与开关探针 PASS；后续 1.9.4 修复审计问题；用户 2026-11-27 验收 RQ-030）
- 适用 Mod：1.9.3
- 游戏基准：v0.111.1 与 v0.113.1

## 1. 用户要求

1. 默认开启 90 天清理。
2. 在 RitsuLib 设置页提供开关，用户可以手动关闭。
3. 清理必须保护当前存档引用的对局数据。
4. 明确标注 1.5.2 删除自动清理是错误的施工。

## 2. 范围

- 恢复对 `contributions/` 顶层旧目录与 legacy 扁平文件的 90 天清理。
- 保护当前单人/多人存档的 `StartTime` 与 seed。
- 设置项写入现有 `mod_prefs.json`；不新增设置文件。
- 不修改战斗归因、统计字段或游戏存档。

## 3. 不做什么

- 不恢复旧版中“删除当前存档引用对局”的风险行为。
- 不增加保留天数滑块；本轮固定 90 天。
- 不清理 `contributions/` 之外的用户文件。
- 不把清理做成运行中定时任务；只在启动时执行一次。

## 4. 设计与验收

- 新增 `ContributionRetention`：
  - 读取当前 `current_run.save` 与 `current_run_mp.save` 的 `start_time` 和 `rng.seed`。
  - 跳过当前存档对应的 Run 目录与 legacy 文件。
  - 跳过 reparse point，避免递归删除越界。
  - 失败只写日志，不影响游戏启动。
- 新增 `ModConfig.AutoCleanupEnabled`，默认 `true`。
- RitsuLib 设置页新增「自动清理 90 天前的贡献数据」开关。
- 启动等待 `SaveManager` profile 初始化后执行；profile 未就绪则跳过，避免误删。

验收：

- AC-036-01：旧目录超过 90 天被删除，未超过保留。
- AC-036-02：当前存档引用的旧目录被保留。
- AC-036-03：当前存档 seed 的 legacy 文件被保留。
- AC-036-04：开关关闭时零删除。
- AC-036-05：设置默认开启；`mod_prefs.json` 可持久化关闭状态。
- AC-036-06：双版本 Release 构建 0 错误。
- AC-036-07：启动加载一次 `v1.9.3 initializing`，清理日志可见。
