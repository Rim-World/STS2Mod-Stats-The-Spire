# 项目范围与验收

## 项目目标

把已停止维护的 Workshop Mod「Stats the Spire」恢复为可构建、可测试、可继续维护的本地源码项目。项目以作者公开的本地版源码为基线，补齐 2026-08-01 Workshop DLL 中的本地功能差异。单一 DLL 目标兼容 Slay the Spire 2 v0.111.1 与 v0.113.1。

成功判据：

1. 源码可以在本机用 `dotnet build` 构建出 `sts2_statsthespire_local.dll`。
2. 游戏 v0.113.1 能加载 DLL，不因 Mod 崩溃。
3. 同一 DLL 兼容 v0.111.1 与 v0.113.1；两个版本均已完成实机验证。
4. 本地统计、战斗贡献、生涯统计、意图状态机、商店价格、药水/卡牌概率等主要功能可用。
5. 2026-08 版本新增的本地功能可用。
6. 源码、文档、测试记录和版本日志完整，后续维护者可以按文档复现。

## 非目标

- 不恢复联网上传、社区统计、账号、服务器接口。
- 不改变游戏平衡、不写入游戏存档、不修改游戏本体文件。
- 本阶段不发布新的 Steam Workshop 物品。
- v0.111.1 与 v0.113.1 的 1.4.4 实机验证已完成；不再复测 1.4.3。
- 不重写 Mod 的统计模型或 UI 设计。

## 用户与使用场景

用户是 Slay the Spire 2 的单人玩家，使用本地 Mod 查看：

- 本场战斗中卡牌、遗物、药水、能力的贡献。
- 本局汇总和单局回放。
- 个人生涯统计与对局筛选。
- 怪物意图状态机。
- 药水掉落、卡牌稀有度、问号房间、商店价格等概率信息。
- 百科大全中的本地卡牌/遗物统计。

## 功能需求

### RQ-001 保持纯本地、离线运行

- 优先级：高
- 验收标准：本地构建不包含联网上传、更新检查、历史导入组件；运行时不发起 HTTP 请求；设置文件中没有服务器地址、上传开关等字段。
- 状态：已实现
- 来源：用户要求；公开源码 README；Workshop 1.3 本地版差异

### RQ-002 兼容 Slay the Spire 2 v0.113.1

- 优先级：高
- 验收标准：对 `v0.113.1` 的 `sts2.dll`、`GodotSharp.dll`、`0Harmony.dll` 构建通过，错误数为 0；游戏加载后日志无未处理异常；主要补丁目标存在。
- 状态：已实现
- 来源：用户要求；本机 `release_info.json`

### RQ-003 同一 DLL 同时兼容 v0.111.1 与 v0.113.1

- 优先级：高
- 验收标准：只构建一个 `sts2_statsthespire_local.dll`；同一文件在 v0.111.1 与 v0.113.1 均可加载；不生成按游戏版本区分的第二份 DLL；版本差异使用运行时探测，不使用编译期版本常量。
- 状态：已实现（v0.111.1 与 v0.113.1 的 1.4.4 实机均已通过）
- 来源：用户要求

### RQ-004 移植 2026-08-01 Workshop 1.3 的本地功能差异

- 优先级：高
- 验收标准：以下功能可见且可用：
  - 生涯统计的对局模式筛选（全部/标准/自定义/每日/多人）。
  - 生涯统计的每局平均用时、卡组大小、遗物数、卡牌类型与稀有度。
  - 贡献面板可拖动改变大小，并记住尺寸。
  - 药水掉落与卡牌掉落两个独立开关。
  - Fiddle、PaleBlueDot、VoidForm 的贡献归因。
  - Neow 选项池从游戏模型动态补充。
- 状态：已实现
- 来源：Workshop DLL 与公开源码的差异分析

### RQ-005 补丁失败不阻断游戏

- 优先级：高
- 验收标准：单个 Harmony 补丁目标缺失时，记录警告并继续加载；不因补丁异常导致游戏崩溃或主循环中断。
- 状态：已实现
- 来源：公开源码 `Safe` 机制；Workshop 1.3 行为

### RQ-006 兼容既有本地数据与设置

- 优先级：中
- 验收标准：继续使用 `%AppData%/sts2_community_stats`；旧 `settings.json`/`mod_prefs.json` 可以读取；旧贡献数据与生涯缓存不因升级损坏；新增字段缺失时使用默认值。
- 状态：已实现
- 来源：公开源码数据路径；Workshop 1.3 配置差异

### RQ-007 版本号、manifest 与构建产物一致

- 优先级：中
- 验收标准：`manifest.json`、`ModConfig.ModVersion`、源码 `CHANGELOG.md`、`7.ChangeLog` 与输出目录均为 `1.4.3`；DLL 文件名为 `sts2_statsthespire_local.dll`。
- 状态：已实现
- 来源：项目版本管理规范

### RQ-008 完成构建、实机测试与清理

- 优先级：高
- 验收标准：保存构建日志与测试日志；至少完成一次游戏启动和一次战斗流程；测试部署从游戏 `mods` 目录移除；游戏进程关闭；测试痕迹清理。
- 状态：已实现
- 来源：用户要求；AGENTS.md 测试规范

### RQ-009 为未来公开发布保留合规与文档条件

- 优先级：中
- 验收标准：README、CHANGELOG、构建说明、许可证状态和作者授权状态有明确记录；不包含用户隐私、密钥、测试账号或本机绝对路径以外的敏感信息。
- 状态：未开始
- 来源：用户说明「未来可能公开发布」

### RQ-010 愚者历史记录与角色筛选可用

- 优先级：高
- 验收标准：生涯统计角色筛选包含「愚者」；选择愚者后只统计本地玩家角色为 `FOOL` 的历史；愚者卡牌与遗物名称显示为游戏本地化名称；愚者历史数据可加载且不报错。
- 状态：已实现（v0.113.1 完整；v0.111.1 仅历史读取，界面无愚者入口）
- 来源：用户要求；本机 15 局愚者历史

### RQ-011 使用 RitsuLib 设置页并支持 F8 重绑定

- 优先级：中
- 验收标准：设置页由 RitsuLib 模组设置入口提供，在主菜单、跑局暂停、战斗暂停均可打开；语言、意图面板缩放和 8 个功能开关可修改并持久化；F7 不再打开旧自绘设置页；贡献面板热键默认 F8，可在设置页重新绑定，重启后保持；不要求安装 BaseLib。
- 状态：已实现（v0.111.1 与 v0.113.1 的页面构建、绑定写入、F8/F9 重绑定已验证；暂停页手工打开未验证）
- 来源：用户要求（2026-11-19）

### RQ-012 同种子对局数据隔离

- 优先级：高
- 验收标准：同 seed 的多次对局按 `StartTime` 分开存储；新局不加载同 seed 的旧 `live`、商店购买或商店报价数据；历史回放按 `StartTime` 找到对应贡献；旧版 seed 文件可只读回退，不自动破坏性迁移。
- 状态：已实现（v0.111.1 与 v0.113.1 同 seed 多局已验证）
- 来源：用户要求；v0.113.1 种子 41111 污染报告

## 非功能需求

- 性能：启动时不得阻塞游戏主线程超过 2 秒；统计加载在后台线程执行。
- 稳定性：所有补丁入口使用异常隔离；缺失游戏类型时降级，不抛出到游戏主循环。
- 兼容性：以 `net9.0` 为目标框架；引用游戏自带的 `sts2.dll`、`GodotSharp.dll`、`0Harmony.dll`。
- 可维护性：源码使用公开仓库的文件组织；版本差异用运行时探测，禁止按版本生成不同 DLL。
- 隐私：不采集、不上传用户数据；不包含个人信息。
