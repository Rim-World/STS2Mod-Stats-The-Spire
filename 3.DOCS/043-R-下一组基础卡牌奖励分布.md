# 下一组基础卡牌奖励分布

- 编号：043-R
- 时间：2026-11-25 07:56
- 适用版本：Mod 1.9.5；游戏 v0.113.1 运行验证，v0.111.1 仅编译验证
- 需求：RQ-031、AC-031
- 计划：`2.PLANS/038-S-下一组基础卡牌奖励分布.md`

## 1. 结论

1.9.5 已把顶栏卡牌面板的主指标改为「下一组基础卡牌奖励」的稀有数量分布。默认组为 3 张；「吃不完的糖」触发时为 4 张；分布按游戏连续保底顺序精确枚举，不使用独立单张概率相乘。

## 2. 实现

### 2.1 纯计算组件

`9.SRC/src/Util/CardRewardGroupOdds.cs` 新增：

- `CardRewardRollProfile`：每个卡位的滚动静音模式（`Offset`、`Base`、`FixedRare`）。
- `CardRewardGroupOdds.Calculate`：按顺序展开概率树，返回 0..N 张稀有的分布与至少 1 张稀有的概率。
- `CardRewardGroupOdds.WillLastingCandyAddFourthCard`：按当前 `CombatRewardsSeen` 预测下一次奖励是否追加第 4 张。

关键规则来自游戏源码：

- `CardRarityOdds.Roll`：稀有重置偏移；非稀有增长偏移；上限 `0.4`。`MegaCrit.Sts2.Core.Odds/CardRarityOdds.cs`。
- `CardFactory.RollForRarity`：先滚动原始稀有度，再按卡池可用性映射；映射不改变原始结果对偏移的推进。`MegaCrit.Sts2.Core.Factories/CardFactory.cs`。
- `LastingCandy.BeforeCombatRewardOffered` 在卡牌生成前递增 `CombatRewardsSeen`；`TryModifyCardRewardOptions` 在该次奖励中以奇数计数追加能力牌；第 4 张使用 `RollWithBaseOdds`。`MegaCrit.Sts2.Core.Models.Relics/LastingCandy.cs`。
- `RewardsSet` 先建立基础卡牌奖励，再把额外奖励组追加到奖励集合。`MegaCrit.Sts2.Core.Rewards/RewardsSet.cs`。

### 2.2 顶栏面板

`9.SRC/src/UI/CardDropOddsIndicator.cs`：

- 标题：`下一组基础卡牌奖励`。
- 副标题区分 3 张组与 4 张组。
- 表格保留普通战斗、精英战斗双列，行显示 0..N 张稀有与至少 1 张稀有。
- Boss 显示本组全部稀有。
- BigGameHunter 精英把共享 `CardCreationOptions` 改为 `Uniform` 且只保留稀有；糖果第 4 张复用该改写，因此本组全部稀有，且只有卡池存在稀有能量牌时才追加第 4 张。
- 表格下方标注额外奖励组不计入本组。
- 计算异常显示「概率不可用」，不向游戏主循环抛出。

### 2.3 组大小预测

`CardRewardsSeen` 在奖励生成前递增，因此顶栏预测的是下一次奖励：

| 当前计数 | 下一次计数 | 糖果是否追加第 4 张 |
|---:|---:|---|
| 0 | 1 | 是 |
| 1 | 2 | 否 |
| 2 | 3 | 是 |
| 3 | 4 | 否 |

没有糖果或卡池没有能力牌时始终为 3 张。

## 4. 已知限制

- 当前只处理卡池初始缺少某档稀有度时的映射；不模拟同一稀有度被黑名单耗尽后的动态变化。
- 不模拟第三方模组修改卡池、奖励钩子或 `CardCreationOptions` 的行为；四张奖励在正常卡池中不足以改变稀有度可用集合。
- 当前面板不合并转经轮、白星、狩猎的额外奖励组，也不计算它们对后续偏移的影响；只按要求标注。
- v0.111.1 只完成编译；`LastingCandy.CombatRewardsSeen` 在 v0.111.1 源码中存在，但未做运行验证。
