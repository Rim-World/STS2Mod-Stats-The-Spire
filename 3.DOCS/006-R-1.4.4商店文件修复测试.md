# 1.4.4 商店文件误读修复测试

- 测试时间：2026-11-19 20:41 至 20:43
- 测试对象：`sts2_statsthespire_local.dll` 1.4.3 与 1.4.4
- 游戏：Slay the Spire 2 v0.111.1
- 方式：无头启动、聚焦探针、同一测试种子对照

## 结论

1.4.3 会把 `codextest_shop_shop_purchases.json` 当成贡献文档读取，产生 1 条警告。1.4.4 加入 `_shop_purchases` 跳过规则后，同一测试不再产生警告，战斗贡献仍正常合并。

## 原因

`AssembleFromCombats` 使用 `{seed}_*.json` 扫描共享贡献目录。商店购买文件也匹配该通配符。

商店购买文件的根节点是 JSON 数组：

```json
[{"ItemId":"TEST_CARD","ItemType":"card","Cost":1,"Floor":1}]
```

贡献文档的根节点是 JSON 对象：

```json
{"Seed":"codextest_shop","Floor":1,"Kind":"combat","Sources":[...]}
```

`JsonSerializer.Deserialize<ContributionDoc>` 无法把数组转换为对象，抛出异常。异常被 `TryLoadDoc` 捕获，记录警告并返回 `null`。因此没有数据丢失，但日志出现噪声。

## 修复

`9.SRC/src/Util/ContributionPersistence.cs:194-196`：

```csharp
if (name.EndsWith("_shop_purchases", StringComparison.Ordinal)) continue;
```

- `codextest_shop_1.json`：一个有效战斗贡献文档。
- `codextest_shop_shop_purchases.json`：一个商店购买数组。

探针调用 `ContributionPersistence.AssembleFromCombats("codextest_shop")`。

| 1.4.3 | 1 | `sources=1` | `8.TEST/1.4.4/v111.1-shopfileprobe-1.4.3-stdout.log:2021` |
| 1.4.4 | 0 | `sources=1` | `8.TEST/1.4.4/v111.1-shopfileprobe-1.4.4-stdout.log:2096` |

1.4.3 警告原文：

```text
[WARN] [StatsTheSpire] ContributionPersistence: load codextest_shop_shop_purchases.json failed: The JSON value could not be converted to CommunityStats.Util.ContributionPersistence+ContributionDoc. Path: $ | LineNumber: 0 | BytePositionInLine: 1.
```

1.4.4 日志中没有 `load ..._shop_purchases.json failed`。
