## 2. 已检查点

1. **战败与胜利的 flush 时序**
   - 战败：`CombatManager.LoseCombat()` 只挂起 loss；Mod 的 `AfterLoseCombat` Postfix 先记录 `PlayerDied` 并首次 flush；之后的 `ProcessPendingLoss()` 触发 `CombatManager.CombatEnded`，保存标志已置位，不重复。
   - 胜利：`CombatRoom.OnCombatEnded()` → `Hook.AfterCombatVictory()` → `CombatManager.CombatEnded`；燃烧之血/黑暗之血治疗在 flush 前进入刚结束战斗。
   - `RunManager.OnEnded` 前缀是兜底；下一场 `AfterSetUpCombat` 重置保存标志。
2. **生成卡来源与奥斯提死亡**
   - `RecordCardOriginInternal` 的 power > relic > potion > card 与 `ResolveSource` 一致。
   - `OstyDeathPatch` 在 v0.111.1 绑定集合 `Kill(IReadOnlyCollection<Creature>, bool)`；单目标重载转调集合，不会双触发。
3. **治疗后路由**
   - `_liveCombatInProgress` 在战后治疗期间保持 true；`OnCombatEnd` 后置 false；晚到的 UI 刷新不能把它翻回 true。
4. **愚者内容运行时注册**
   - 全部类型/方法使用字符串 + `AccessTools.TypeByName`/`DeclaredMethod`；v0.111.1 实机日志确认 34 条目标逐项跳过。
   - BathRobes 已从 `FoolContentPatch` 排除，避免与 `RelicHookContextPatcher.TryPatchTypeName` 双注册。
5. **P1 遗物来源**
   - `RuinedHelmet`、`SneckoSkull`、`UnsettlingLamp` 的 capture 有 canonical、owner、amount 守卫；commit 前检查既有来源。
   - 未发现确定性重复计数或空引用。

## 3. 审阅发现与处理

- 未发现确定性缺陷。
- 原审阅过程曾怀疑 `LoseCombat` 内同步触发 `CombatEnded`；反编译 v0.113.1 后确认 `LoseCombat` 只设置 `PendingLoss`，该怀疑撤回。
