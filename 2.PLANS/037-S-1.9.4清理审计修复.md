## 2. 审计发现

独立 reviewer 对提交 `7722f5e` 与 `10.OUTPUT/1.9.3` 判定 FAIL：

- `SaveManager.GetProfileScopedPath` 返回 `user://...`；1.9.3 直接交给 `System.IO.File.Exists`，当前存档保护恒为空。
- 只读取当前 profile；其他 profile 的暂停局仍可能被清理。
- 清理所有顶层旧目录，未限制为 `{StartTime}_{seed}` Run 目录。
- 仅检查顶层 reparse point；嵌套 junction/symlink 可能造成部分删除或异常。
- 探针只打印 `hasSave=False` 而不纳入 PASS，导致上述路径缺陷仍显示 PASS。

## 3. 施工范围

- `ResolveFileSystemPath` 将 `user://`/`res://` 转为 OS 路径；空路径视为解析失败并跳过清理。
- 读取 `ProfileSaveManager.maxProfileCount` 个 profile 的 saves 目录；合并所有 `start_time` 与 `rng.seed`。
- 目录名只接受 `{正 long}_{seed}`；未知目录保留。
- 删除前递归预扫描 reparse point；命中则跳过整个 Run 目录。
- 探针增加真实路径、三 profile 路径、多目录合并、真实 `current_run.save` 保护旧目录的用例。
- 版本升至 1.9.4，更新输出包、文档和测试登记。

## 4. 不做什么

- 不改战斗归因、统计字段、游戏存档或清理天数。
- 不清理 `contributions/` 以外文件。
- 不在运行期定时清理。
- 不构造真实多 profile 暂停局；用合成 saves 目录覆盖合并逻辑，并断言真实三个 profile 的 saves 路径可解析。
