# 下一组基础卡牌奖励分布

- 计划编号：038-S
- 建立时间：2026-11-25 07:29
- 状态：未开始
- 适用 Mod：1.10.0（计划）
- 游戏基准：v0.111.1 与 v0.113.1
- 需求：RQ-031、AC-031

## 1. 目标

把顶栏卡牌掉率面板从「下一张卡位的单卡稀有度」改为「下一组基础卡牌奖励的稀有度数量分布」。

面板必须显示：

1. 本组 0 张、1 张……N 张稀有的概率。
2. 本组至少 1 张稀有的总概率。
3. 本组张数与「吃不完的糖」状态。
4. 本组不包含转经轮、白星、狩猎产生的额外奖励组。

## 2. 现状

`9.SRC/src/UI/CardDropOddsIndicator.cs:101` 只缓存 `CardRarity.CurrentValue`。悬停面板在 `:134-145` 分别计算普通战斗与精英战斗的单张稀有、罕见、普通概率，再按行显示。标题与副标题仍是「下一场 / 单张卡牌」口径。

游戏侧的真实行为：

- `CardFactory.CreateForReward` 在 `MegaCrit.Sts2.Core.Factories/CardFactory.cs:90-110` 逐张生成奖励，同一奖励默认 3 张。
- `CardRarityOdds.Roll` 在 `MegaCrit.Sts2.Core.Odds/CardRarityOdds.cs:82-93` 使用并推进共享偏移；出稀有重置到 `-0.05`，非稀有增加 `RarityGrowth`，上限 `0.4`。
- 普通与精英基础值在 `CardRarityOdds.cs:43-53`；A7+ 由 `AscensionLevel.Scarcity` 切换。
- 负偏移同时降低罕见阈值；`CardRarityOdds.cs:110-125` 的罕见阈值是「罕见基础值 + 当前稀有阈值」。
- 「吃不完的糖」在 `LastingCandy.cs:102-149` 追加第 4 张能力牌；该牌走 `RollWithBaseOdds`，不读取当前偏移，也不推进共享偏移。
- 转经轮、白星与狩猎的额外奖励在基础奖励之后加入；`RewardsSet.cs:97-100` 追加额外奖励，基础奖励已先在第 `133-136` 行生成。白星额外组使用 Boss 表并把共享偏移重置；转经轮与狩猎额外组使用并推进共享偏移。
- `BigGameHunter.cs:34-58` 把精英奖励限制为稀有；`RewardsSet.cs:225-244` 仍按普通、精英、Boss 的实际奖励表加入卡牌奖励。

## 3. 范围

- 新增纯计算组件，计算基础组 0..N 张稀有的分布。
- 修改 `CardDropOddsIndicator` 的标题、副标题、表格与额外组说明。
- 检测当前玩家是否为「吃不完的糖」触发轮次，并确定本组为 3 张还是 4 张。
- 保持 Boss、精英、普通、BigGameHunter 与极速模式的现有规则。
- 增加固定夹具、双版本构建与运行探针。
- 更新 SPEC、SDD、测试登记、版本日志和输出包。

## 4. 不做什么

- 不计算某一张具体卡牌出现的概率；只计算稀有度数量分布。
- 不把转经轮、白星、狩猎的额外组并入基础组。
- 不随机模拟游戏 RNG；使用精确概率枚举。
- 不修改游戏平衡、游戏存档或既有战斗统计。
- 不为 v0.111.1 单独生成 DLL。
- 不处理未要求的面板美化或热键改动。

## 5. 计算模型

### 5.1 输入

纯计算组件接收以下输入：

- 当前共享偏移 `offset`。
- 奖励表类型：普通、精英、Boss、BigGameHunter 精英。
- 基础稀有概率 `baseRare`。
- 基础罕见概率 `baseUncommon`。
- 偏移增长 `growth`。
- 基础组张数：3 或 4。
- 第 4 张是否为「吃不完的糖」能力牌。

普通与精英的基础值直接取 `CardRarityOdds.RegularRareOdds`、`EliteRareOdds`、`regularUncommonOdds`、`eliteUncommonOdds` 与 `RarityGrowth`。Boss 与 BigGameHunter 走固定结果，不套用普通偏移。

### 5.2 三张基础组

每一张卡位按以下规则计算：

```text
rareThreshold = baseRare + offset
pRare       = clamp(rareThreshold, 0, 1)
pUncommon   = clamp(baseUncommon + min(0, rareThreshold), 0, 1)
pCommon     = clamp(1 - pRare - pUncommon, 0, 1)
```

结果分支：

```text
稀有：offset = -0.05
非稀有：offset = min(offset + growth, 0.4)
```

不得使用「独立单张概率直接相乘」。必须枚举 3 个卡位的 3^3 种结果，按实际偏移变化累计 0..3 张稀有的概率。至少 1 张稀有的概率等于 `P(1) + P(2) + P(3)`。

### 5.3 吃不完的糖的第四张

触发条件与游戏一致：

- 当前玩家拥有 `LastingCandy`。
- `CombatRewardsSeen > 0` 且为奇数。
- 当前奖励存在至少一张可生成的能力牌。

前 3 张仍按 5.2 的顺序规则计算。第 4 张：

- 使用基础奖励表 `RollWithBaseOdds` 的概率，不读取当前偏移。
- 不推进共享偏移。
- 其稀有结果计入本组稀有数量。
- 若没有可生成能力牌，本组仍为 3 张，不追加第 4 张。

因此 4 张组的分布是「前 3 张序列分布 × 第 4 张基础分布」，不是 4 张都用当前偏移。

### 5.4 特殊奖励表

- Boss：每张固定稀有，本组 N 张稀有概率为 100%。
- BigGameHunter 的精英：每张固定稀有，本组 N 张稀有概率为 100%。
- 普通、精英：按 5.2 与 5.3 计算。
- 「极速」模式：保持现有隐藏逻辑，不显示面板。

### 5.5 额外奖励组

基础组计算不包含以下奖励：

| 来源 | 额外组规则 | 对共享偏移 |
|---|---|---|
| 转经轮 | 普通表 3 张 | 使用并推进 |
| 白星 | Boss 表 3 张固定稀有 | 自身生成后重置共享偏移 |
| 狩猎 | 当前房间表 3 张 | 使用并推进 |

面板必须显示「本组不含额外奖励组」。不得写成「额外组完全不影响偏移」。如果用户后续要求把额外组也列入，再另开计划；本计划不扩大范围。

### 5.6 池可用性

首轮只按当前卡池可用的稀有度集合处理：

- 某稀有度完全无可用卡时，按游戏 `GetNextAllowedRarity` 的向上折返规则映射到可用稀有度。
- 不模拟同一稀有度内卡牌被黑名单耗尽后的动态变化；3 张或 4 张奖励在正常卡池中不足以改变稀有度可用集合。
- 该限制必须写入 SPEC 注记，不能把结果说成「任意卡池下绝对精确」。

### 6.2 表格

保留普通战斗、精英战斗两列，避免丢失现有信息。表格行改为：

```text
稀有数量        普通战斗        精英战斗
0 张稀有         x%             x%
1 张稀有         x%             x%
...
N 张稀有         x%             x%
至少 1 张稀有    x%             x%
```

- 行数由本组张数决定，3 张组显示 0..3，4 张组显示 0..4。
- 至少 1 张稀有使用分布求和，不使用 `1 - (1 - p)^N`。
- Boss 保留单行「Boss 奖励：稀有 100%」，并写明本组张数。
- BigGameHunter 的精英列显示全部稀有；普通列保持普通奖励表。
- 额外组说明放在表格下方，使用一行短文本。

## 8. 测试与验收

### 8.1 固定夹具

使用独立探针或测试程序，至少覆盖：

| 用例 | 输入 | 判定 |
|---|---|---|
| A0 普通 3 张，偏移 -0.05 | 基础值 A0 普通 | 分布和为 1；0..3 张稀有均非负；至少 1 张等于 1..3 之和 |
| A7+ 普通 3 张，偏移 0 | Scarcity 基础值 | 与 A0 不同；负偏移时罕见概率下降 |
| 精英 3 张 | A0/A7+ 精英 | 使用精英基础值，不套普通值 |
| 正向偏移 | 0、+0.05、+0.4 | 偏移更新、上限与稀有重置正确 |
| 吃糖 4 张 | 偏移 -0.05；第 4 张基础值 | 第 4 张不读取偏移，不推进偏移；分布和为 1 |
| 无能力牌 | 池内无能力牌 | 本组保持 3 张 |
| Boss | Boss 表 | 本组 N 张稀有概率 100%，至少 1 张 100% |
| BigGameHunter | 精英 | 本组 N 张稀有概率 100% |
| 额外组排除 | 转经轮/白星/狩猎夹具 | 基础组概率不因额外组存在而改变 |
| 白星重置 | 白星额外组生成后 | 仅后续偏移变为 -0.05；不得回写当前基础组结果 |
| 至少 1 张 | 任意分布 | 不得用独立概率公式；必须等于分布尾和 |

### 8.3 失败处理

- 缺少 `LastingCandy` 类型、属性或本地玩家时，回退 3 张组，不抛异常。
- 缺少奖励表或基础常量时，显示「概率不可用」，不显示错误值。
- 极速模式继续隐藏整个面板。
- 计算出现负概率、NaN 或分布和不在 `1 ± 1e-9` 时，记录诊断并回退到安全占位。

## 11. 风险

- 「本组 4 张」只在吃糖触发时出现；从顶栏打开面板到战斗奖励生成之间，状态可能变化。实现时以面板打开时的当前存档状态为准，并在下一帧刷新；不承诺提前预测后续状态。
- 白星额外组会重置共享偏移，但它不参与当前基础组；若后续偏移被其他系统刷新，必须读取游戏当前值，不得用旧缓存。
- 卡池缺稀有度时使用游戏折返规则；不模拟同稀有度卡牌被耗尽。该限制必须写入 SPEC 注记。
- v0.111.1 的 UI 与游戏状态字段需与实际加载验证；不能只依赖编译通过。
