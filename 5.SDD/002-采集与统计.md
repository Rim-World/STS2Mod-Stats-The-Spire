## 依赖

允许：

- `Collection -> Config`：读取 `ModConfig` 的缓存 TTL、数据目录。
- `Collection -> Util`：`Safe`、`CareerStatsCache`、`ContributionPersistence`、`RunStorage`、`AncientPoolMap`。
- `Util/CareerStatsCache -> Collection`：序列化 `CareerStatsData`。

禁止：

- `Collection` 不得引用 `UI` 或 `Patches`。
- `Collection` 不得调用 Godot 节点 API，除非在 `BuildSingleRunStats` 等纯数据函数中不触碰场景树。

静态检查：

```bash
rg -n "Godot\.|Node|Control" 9.SRC/src/Collection
```

允许 `Godot` 仅出现在与游戏模型类型相关的 using 中；出现节点构造即视为越界。

## 数据流

### 战斗内

1. 补丁调用 `CombatTracker.OnCardPlayStarted`、`SetActiveRelic`、`SetActivePotion`、`SetActivePowerSource` 设置来源。
2. 伤害事件进入 `OnDamageDealt`。直接伤害记到当前来源；间接伤害通过 `ContributionMap` 的来源映射分摊。
3. 格挡事件进入 `OnBlockGained` 与 `ContributionMap.AddBlock`，形成可消费的格挡池。
4. 抽牌、能量、治疗、最大生命、星星等事件进入对应 `On*` 方法。
5. `CombatTracker.NotifyCombatDataUpdated` 设置脏标记并在 1 秒后合并写 `LiveContributionSnapshot`；战斗结束与保存退出强制 flush。

### 战斗结束

1. `OnCombatEnd` 生成 `LastCombatData` 与 `LastEncounterId`。
2. `ContributionPersistence.SaveCombat` 通过 `AtomicFile` 写入 `{StartTime}_{seed}/combat_{floor}_{sequence}.json`。
3. `RunContributionAggregator.AddCombat` 合并本局累计。
4. 面板读取 `LastCombatData` 显示。

### 新局与续局

1. `RunLifecyclePatch` 从 `RunManager._startTime` 与 `RunState.Rng.StringSeed` 建立 `RunIdentity`。
2. 新局调用 `RunDataCollector.BeginNewRun`；清空内存，不读取旧 live 与商店文件。
3. 续局调用 `RunDataCollector.ResumeRun`；清空内存后读取当前 RunKey 的 live、商店和贡献文件。1.4.4 及更早存档没有新目录时，允许只读回退到 legacy seed 布局。
4. 对局结束调用 `RunDataCollector.OnMetricsUpload`；有贡献数据时写入 `summary.json`，删除新目录中的 live 与商店报价文件；同一 `RunKey` 只收尾一次。legacy 回退文件不因收尾移动或删除。
5. 如果本次续局的商店购买来自 legacy 文件，收尾时把内存列表复制到当前 RunKey 的 `shop_purchases.json`；旧文件保留，空列表不写文件。
6. `StartTime` 读取失败时使用 legacy seed 路径，并记录警告。

### 生涯统计

1. `LoadAllAsync` 先查内存缓存，再查磁盘缓存。
2. 未命中时读取全部 `RunHistory`，再按筛选条件生成 `loaded`；卡牌/遗物 bundle 始终使用全部历史。
3. `BuildSnapshot` 聚合总览、胜率窗口、死亡原因、路线、先古、Boss 与全局卡牌/遗物 bundle。
4. 结果写入内存与磁盘，通知 UI。

## 不变量

- 同一伤害结果不得重复计入；`MarkDamageResultProcessed`/`IsDamageResultProcessed` 保证幂等。
- `ContributionAccum.TotalDamage` 与 `TotalDefense` 由各分项求和，不得单独改写总分。
- 格挡池消耗不得超过池内余额。
- 生涯缓存键必须包含角色、最低进阶、最近局数和对局模式；任一字段不同即不同缓存。
- `RunHistoryAnalyzer` 的 `SemaphoreSlim` 保证同一时刻只有一个构建任务。
- 同 seed 的不同对局必须由 `StartTime` 区分；新局不得读取旧文件，续局不得读取其他 RunKey。
- 持久化字典键必须使用 `sourceId + \u0001 + originId`；同名生成卡与原生卡不得在加载时合并。
- `live.json` 同一时刻最多一个待写定时器；flush 后必须清脏标记，失败必须恢复脏标记。

## 失败与降级

- 单个 RunHistory 解析失败：跳过该局，记录警告，继续其他局。
- 缓存文件损坏：移动到 `.corrupt-*` 后重建；重建失败返回空 `CareerStatsData`。
- 贡献/商店/运行态 JSON 损坏：移动到 `.corrupt-*`，返回 null，不覆盖原文件。
- 写贡献文件失败：记录警告，不阻断战斗结束。
- 游戏类型缺失：补丁层跳过，统计层不感知。

## 1.6.0 实现状态（部分验证）

本节记录 1.6.0 的已实现代码与未完成边界。对应任务见 `2.PLANS/018-G-1.6.0-战斗归因修复与愚者覆盖.md`。

### 来源栈

- `CombatTracker.CaptureAttributionContext` / `RestoreAttributionContext` 保存并恢复遗物、药水、能力来源。
- 遗物/能力 hook 的前缀保存外层上下文，后缀恢复；嵌套 hook 不再清空外层来源。
- 卡牌上下文和预览调用仍未纳入同一快照；预览隔离仍未完成。

### 资源与生命周期

- 能量、辉星按实际到账记录；手抽加成按实际抽到的第 6 张及以后消费，手牌上限截断不虚增。
- 无星费牌的 canonical 星费按 0 处理，不得记录负值。
- 待定抽牌来源只在抽牌 hook 设置，并有明确清理点。
- 格挡池只在实际清空格挡时清空。
- 战败路径调用与胜利路径相同的战斗收尾和 flush。
- 战斗胜利后的遗物治疗（燃烧之血、黑暗之血、带骨肉）进入刚结束战斗记录，不重复进入本局总计。
- 战斗内首条治疗（包括修书小刀的 Doom 治疗后治疗）按当前战斗处理，不因字典为空写入本局总计。

### 新内容

- 16 张能力牌、15 个遗物、2–3 个非卡牌能力已登记；当前使用遗物/能力上下文快照，卡牌上下文未纳入。
- 新类型只由补丁层运行时注册；采集层不直接引用 v0.113.1 类型。
- 敌人、Dominion、内部状态和事件不进入贡献来源。
