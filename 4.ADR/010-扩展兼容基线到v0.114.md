# 扩展兼容基线到 v0.114

- 状态：已接受
- 日期：2026-11-27
- 当时的项目版本：1.10.0
- 相关文件：`9.SRC/sts2_statsthespire_local.csproj`、`9.SRC/manifest.json`、`9.SRC/src/Patches/CombatHistoryPatch.cs`、`9.SRC/src/Patches/FoolContentPatch.cs`、`1.PRD/001-项目范围与验收.md`、`6.SPEC/001-总体规范.md`

## 背景

游戏从 v0.113.1 更新到 v0.114.0。v0.114.0 的 `Creature.LoseHpInternal`、`CardModel.UpgradeInternal`、`CardModel.DowngradeInternal` 与 `DamageBlockInternal` 签名变化，`FreeCardPower` 删除，`RapidShot` 重做为 `TwinShot`。RitsuLib 0.6.16 才提供 0.114 运行时集成，且同时保留 0.113、0.111 和 0.107.1 的兼容变体。

现有 ADR-005 已确定「单一 DLL + 运行时探测」。本决策只扩展兼容基线，不改变该形态。

## 决策

继续使用一个 `sts2_statsthespire_local.dll`，兼容 v0.111.1、v0.113.1 与 v0.114.0。编译引用使用最低游戏 API 的 `STS2.RitsuLib.Compat.0.111.0` 0.6.16；运行时由 RitsuLib 根据宿主版本选择 0.111、0.113 或 0.114 变体。

## 备选方案

- **分别构建 0.111/0.113/0.114 三份 DLL**：否决。会增加发布、安装和版本不一致风险，违反 ADR-005 和用户要求。
- **只支持 v0.114.0**：否决。0.113.1 稳定分支仍在被玩家使用，旧版本兼容不能无故删除。
- **编译引用 `STS2.RitsuLib` 0.114 主包**：否决。主包把 0.114 类型带入编译，无法保证 0.111 构建和运行时绑定；使用 0.111 compat 包作为最低公共 API。
- **复制 RitsuLib DLL 进本 Mod**：否决。违反硬依赖边界，且会破坏 RitsuLib 自己的加载器与变体选择。

## 后果

- `manifest.json` 的 RitsuLib 最低版本必须是 `0.6.16`；玩家必须安装带对应 compat 变体的完整 RitsuLib 文件夹。
- 每次发布前必须分别用 v0.111.1、v0.113.1、v0.114.0 的 `sts2.dll` 编译；发布 DLL 取一个构建结果。
- 0.114 的版本差异必须继续运行时探测；已知差异包括 HappyFlower 的 `AfterPlayerTurnStartEarly` 与 TunePower 的 `AfterCardPlayed`。
- RitsuLib 0.6.16 尚未在 Steam 过审前，不能发布依赖它的创意工坊版本；否则玩家无法满足依赖。
