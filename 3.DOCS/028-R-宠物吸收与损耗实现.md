# 宠物吸收与损耗实现

- 时间：2026-11-22 09:00

## 结论

1.7.0 已实现独立的 `PetAbsorbed` 与 `PetWasted`。奥斯提/瓦皮吸收不再写入 `EffectiveBlock`；碎骨/牺牲主动击杀奥斯提的剩余 HP 单独显示为红色「宠物损耗」。

## 数据规则

| 字段 | 含义 | 来源 |
|---|---|---|
| `PetAbsorbed` | 宠物替玩家吸收时实际失去的 HP | 奥斯提 LIFO 召唤来源；瓦皮父条 |
| `PetWasted` | 主动击杀宠物浪费的剩余 HP | 仅 `BONE_SHARDS`、`SACRIFICE` |
| `EffectiveBlock` | 真实格挡吸收 | 只由格挡池消耗写入 |

防御总量：

```text
EffectiveBlock
+ PetAbsorbed
+ ModifierBlock
+ MitigatedByDebuff
+ MitigatedByBuff
+ MitigatedByStrReduction
+ UpgradeBlock
- SelfDamage
- PetWasted
```

## 未验证与限制

- 游戏内真实 Wuppy、碎骨、牺牲在 v0.113.1 通过；v0.111.1 只做构建与数据探针，未安装运行。
- 人工界面视觉验收：未做；探针检查了文字、行、颜色和百分比，不代替真人视觉。
- 旧数据中已经与正格挡相抵的负值无法还原为 `PetWasted`；保留原值。
- 旧奥斯提父条与召唤卡子条的迁移依赖 `OriginSourceId`；缺失该字段的旧子条无法识别。
- `PetWasted` 只对两张卡开放；未来新增主动击杀卡必须更新允许名单。

## 独立审阅

独立审阅发现 1 个阻断项、1 个高项、1 个中项和 1 个低项：

| 级别 | 问题 | 处理 |
|---|---|---|
| 阻断 | 非防御分节用 `PositiveDefense` 判断行，导致伤害/抽牌/能量/辉星/治疗行丢失；自伤/宠物损耗红行泄漏到所有分节 | 已修：按 `Category` 使用 `value > 0`；成本行只允许 Defense |
| 高 | `PetWasted` 用 LIFO 堆栈而非 Osty 实际当前 HP；治疗和续局会错 | 已修：`OstyDeathPatch` 传入 `(int)creature.CurrentHp`；堆栈只负责吸收归因 |
| 中 | 损耗条比例未计入 `SelfDamage`/`PetWasted`，可超出 380px | 已修：顶层与子条 `maxVal` 计入成本 |
| 低 | 生成卡的 `PetWasted` 落在子条时不显示专用红行 | 已修：子条循环拆分成本行 |

修复后重新构建 v0.113.1 与 v0.111.1，均 0 错误。独立复测 51/51 PASS：非防御分节恢复、子条损耗行与柱宽正确、治疗后实际 HP 计入损耗。

复审结论：四项发现（阻断/高/中/低）均已解决，无新增阻断、高、中问题。剩余两个低项已在本轮修复：独立自伤行显示来源名；生成卡 `PetWasted` 固定写顶层。最终聚焦复测 34/34 PASS。
