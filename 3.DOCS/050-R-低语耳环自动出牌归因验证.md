# 低语耳环自动出牌归因验证

- 编号：050-R
- 时间：2026-11-28 19:07
- 适用版本：Mod 1.12.0；游戏 v0.114.0；RitsuLib 0.6.16
- 需求：RQ-034、AC-033
- 结论：低语耳环的自动出牌已归到 `WHISPERING_EARRING` 遗物根来源。v0.114.0 定向探针 PASS：自动次数 2、直接伤害 32、有效格挡 5、手动次数 0、能量 1；自动牌 `BLUDGEON` 与 `DEFEND_SILENT` 没有自动子行。v0.113.1 与 v0.111.1 仅构建，未运行。

## 1. 实现

`9.SRC/src/Patches/CombatHistoryPatch.cs` 的 `RelicHookContextPatcher` 增加：

```csharp
TryPatch(harmony, typeof(WhisperingEarring),
    "AfterAutoPrePlayPhaseEnteredLate", prefix, postfix);
```

该 patch 复用现有遗物上下文：

- `SetRelicContext` 设置 `_activeRelicId=WHISPERING_EARRING`；
- `CardCmd.AutoPlay` 进入 `CombatTracker.OnCardPlayStarted` 时，`ResolveAutoPlayRoot` 返回遗物来源；
- 自动牌不建立自己的贡献行；每张自动牌增加遗物行 `AutoPlayedCount`；
- `ClearRelicContext` 恢复调用方上下文。

没有新增统计字段，没有改动持久化格式。

## 2. 探针

工程：`8.TEST/1.12.0/EarringProbe/`。

测试流程：

1. 用 AutoSlayer 启动标准种子 62005，进入第一场战斗。
2. 暂停 AutoSlayer 的战斗循环 `CombatRoomHandler.PlayCombatAsync`，避免它同时出牌并结束回合。
3. 等待第一回合 Play 阶段。
4. 清空自然手牌，加入 `BLUDGEON` 与 `DEFEND_SILENT`。
5. 在 Play 阶段添加 `WhisperingEarring`，避开自然首回合 hook；随后调用真实 `AfterAutoPrePlayPhaseEnteredLate`。
6. 检查遗物行、自动次数、直接伤害、自动牌子行与能量。
7. 结束回合并等待敌方攻击，检查 `EffectiveBlock` 与 +1 能量。
8. 输出 `RESULT PASS` 后退出游戏。

AutoSlayer 的 `CardCmd.AutoPlay` 在探针外部被阻断，避免污染。探针只调用真实 hook，不手工伪造 `OnCardPlayStarted`。

## 4. 失败记录与修正

### 4.1 第一次：AutoSlayer 抢先结束回合

日志：`8.TEST/1.12.0/earring-probe-stdout.log`。

结果：`auto=1`。AutoSlayer 在探针准备确定性手牌时同时调用 `CardCmd.AutoPlay`，随后结束回合；探针只来得及自动打出 1 张牌。

修正：探针在初始化时 Harmony patch `CombatRoomHandler.PlayCombatAsync`，让 AutoSlayer 只负责启动跑局，不参与战斗回合。

### 4.2 第二次：错误地要求战前 `EffectiveBlock`

日志：`8.TEST/1.12.0/earring-probe2-stdout.log`。

结果：`auto=2`、`direct=32`、`block=0`。

原因：`EffectiveBlock` 是实际吸收伤害的格挡，不是打出的格挡值；没有敌方攻击时必然为 0。

修正：自动出牌后结束回合并等待敌方攻击，再检查 `EffectiveBlock=5` 和下一回合 `EnergyGained=1`。

## 7. 结论

核心归因路径已验证。低语耳环现在与乱战、惊逃、傻瓜采用同一根来源口径：自动打出的牌归到发起自动链的遗物行，不生成自动牌行，遗物自身能量不重复计入。
