# 宠物损耗使用独立字段

- 状态：已接受
- 日期：2026-11-22
- 项目版本：1.6.1（决策时）；目标版本 1.7.0
- 相关文件：`1.PRD/001-项目范围与验收.md`、`2.PLANS/024-M-宠物吸收统计与展示.md`、`4.ADR/007-宠物吸收使用独立字段.md`、`9.SRC/src/Collection/ContributionMap.cs`、`9.SRC/src/Collection/CombatTracker.cs`、`9.SRC/src/Patches/CombatHistoryPatch.cs`

## 背景

当前实现把奥斯提死亡时剩余 HP 作为负防御，延迟到下一次敌人受击时从击杀卡的 `EffectiveBlock` 扣除。

这会产生两个口径混合：

- 实际有效格挡：卡牌实际吸收的伤害。
- 净防御：再扣掉「浪费宠物 HP」的机会成本。

用户已选择 D：新增独立字段 `PetWasted`，把机会成本与实际格挡分开。

主动杀死奥斯提的卡牌只有两张：

- `BoneShards`：`BoneShards.cs:41`
- `Sacrifice`：`Sacrifice.cs:39`

v0.107、v0.111.1、v0.113.1 的三个版本中，主动击杀路径都只有这两张牌。`CreatureCmd.cs:659` 是玩家死亡时清理奥斯提，不属于主动击杀。

玩家不能主动杀死瓦皮。瓦皮承受敌方攻击属于生命值吸收，不属于本决策的宠物损耗。

## 决策

新增 `PetWasted` 字段，记录主动击杀宠物时浪费的剩余 HP。

规则：

1. `PetWasted` 是非负整数，单位是 HP。
2. 只有 `BONE_SHARDS` 和 `SACRIFICE` 主动击杀奥斯提时，才写入 `PetWasted`。
3. 写入值等于击杀时的奥斯提剩余 HP。
4. `PetWasted` 立即写入击杀卡，不再延迟到下一次敌人攻击。
5. `EffectiveBlock` 只记录实际格挡，不再扣减宠物损耗。
6. `PetAbsorbed` 只记录宠物实际吸收的伤害，不记录宠物损耗。
7. `TotalDefense` 减去 `PetWasted`。
8. 瓦皮不产生 `PetWasted`。
9. 旧 JSON 中可识别的负 `EffectiveBlock` 迁移到 `PetWasted`，保持总防御不变。
10. 新增主动击杀宠物的卡牌必须加入允许名单，并补测试。

## 备选方案

### A：删除负防御

优点是改动最小。

缺点是丢失「牺牲宠物剩余 HP」的成本信息。否决。

### B：把负值改记到 `PetAbsorbed`

优点是仍然使用一个宠物字段。

缺点是 `PetAbsorbed` 同时表示吸收和损耗，字段名与数值含义冲突。否决。

### C：继续留在 `EffectiveBlock`

优点是几乎不改代码。

缺点是 `EffectiveBlock` 无法再表示实际格挡，违反 ADR-007。否决。

## 后果

获益：

- 实际格挡与机会成本分开，口径清楚。
- 碎骨和牺牲的剩余 HP 损失可以单独展示和核对。
- 瓦皮不会产生不存在的主动击杀损耗。
- 旧负值可以迁移，不改变历史总防御。

代价与约束：

- `ContributionAccum`、DTO、JSON、live 快照、summary、汇总和 UI 全部要同步。
- 只有两张卡触发；新增击杀卡必须更新允许名单。
- 旧数据只有负 `EffectiveBlock` 可以识别并迁移；已经与正格挡相抵的旧值无法还原。
- `PetWasted` 不得进入正向防御百分比的分母。
- UI 必须与自伤行分开，避免把宠物损耗叫作自伤。
